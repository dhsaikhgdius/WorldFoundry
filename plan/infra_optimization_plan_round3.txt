WorldFoundry 基础设施优化计划（第 3 轮）
========================================
日期：2026-08-25
性质：建议修改（本文件只记录计划，不直接改代码）
承接：plan/infra_optimization_plan.txt（第 1 轮）、plan/infra_optimization_plan_round2.txt（第 2 轮）
方法：主会话编排 + 云端子代理并行评审（模型 claude-fable-5-thinking-xhigh）
  - 训练启动 / recipe / checkpoint / post-training reward 作业
  - 数据集与 checkpoint 下载流水线
  - CLI 冷启动残余、operators 设备、密钥落盘、scripts 膨胀、dino_wm SLURM
  - Studio 服务面由主会话只读补全（该方向云端评审触发了内容策略拦截，未做攻击面展开）

本轮不重复：Docker/CI/conda/DLC/device_pool、LFS/wheel、catalog binding、generation cache WAL、
sp logger stdout、metric_sync HOSTNAME、native-kernels CI、gradio pin。


0. 现状一句话
--------------
训练引擎的 checkpoint 协议已经扎实，缺口在「抢占/信号/reward 侧车」。
下载链路有五套入口、三套 ready 判定，半截下载会被当成完整资产。
公共 CLI 仍有密钥进 scorecard argv、以及 wheel 安装后 zoo download 直接 ImportError。


1. 不建议改的地方
------------------
- 不要动 training/distributed/parallel.py 的 torchrun 边界。
- 不要放松 checkpointer 的「step 目录已存在则失败、output_dir 必须全新」。
- 不要在信号/异常路径新增集合通信。
- 不要把 reward URL 写进 recipe；只补超时/重试/预检。
- 不要为未接线的 ~18 种 post-train 算法批量写 CLI 分支；矩阵数据化 + 早失败即可。
- 不要给全部 HF repo 建人工 sha256 清单；revision pin + hub etag 是正路，只给绕过 hub 的镜像补点状校验。
- 不要把 download_hfd_models.sh 强行并进 Python。
- 不要默认开启 HF_HUB_ENABLE_HF_TRANSFER。
- 不要给 90 个 operator 换 entry_points 自动注册。
- 不要删除 scorecard.run.command，只脱敏。
- 不要改 runtime/env.py 与 run_manifest.redact_secrets 另起第三套脱敏。
- 第 1–2 轮已划边界继续有效。

3. 训练启动 / checkpoint / post-training
----------------------------------------
现状
  生产入口已收敛到 worldfoundry train / post-train；默认输出 runs/（已 gitignore）。
  TrainingCheckpointer：staging → manifest+_SUCCESS → fsync → os.replace，质量高。
  keep-last-N 只有环境变量 WORLDFOUNDRY_TRAINING_CHECKPOINT_KEEP_LAST。
  训练树 grep 无 signal/SIGTERM/KeyboardInterrupt。
  ScorerServiceConfig.from_mapping 默认 host 0.0.0.0；HTTPRewardEvaluator 调用点 retry_attempts=0。

建议修改

[T-01] P1 无信号/中断落盘
  文件：worldfoundry/training/engine/sessions/single_device.py
        worldfoundry/training/engine/wan/flow_policy_run.py 及同类 run
  改法：SIGTERM/SIGINT 置位、step 边界尽力存盘、manifest status=interrupted；
        except Exception 扩为 BaseException 中的 KeyboardInterrupt 分支（只写状态不吞）。
        多 rank 只做本 rank 动作，不加 barrier。

[T-02] P1 reward 服务默认绑定未闭环
  文件：worldfoundry/training/post_training/rewards/scorers/service_config.py
        rewards/http/service.py 、 client.py
        configs/post_training/reward_service_*.yaml
  改法：from_mapping 默认 127.0.0.1；非回环启动打 warning；
        可选 server.auth_token_env；请求条数/解码字节上限。
  交叉：与第 1 轮 embodied model_server 0.0.0.0 同模式，这是训练侧车，未写过。

[T-03] P1 reward 客户端零容错
  文件：engine/video_policy.py 、 post_training/causal_lm/qwen3/materializer.py
        recipes/post_training/rewards/remote.py
  改法：构造后 health()；校验 reward_ids 覆盖 recipe；RemoteRewardSpec 加 timeout/retry；默认重试 2–3。

[T-04] P2 无 auto-resume 编排
  文件：cli/training_commands/handlers/train.py
  改法：--resume-from-run RUN_DIR，内部用 checkpointer._resolve("latest")。

[T-05] P2 post-train 矩阵硬编码
  文件：cli/training_commands/handlers/post_train.py
  改法：{algorithm: (families, materializer, flags)} 声明表；未接线早失败；--list-support --json。

[T-06] P2 keep_last 配置面
  文件：training/recipes/spec.py CheckpointSpec 、 session 构造
  改法：recipe 字段 + env 覆盖；生效值写入 run manifest；可选 statvfs 预检。

[T-07] P2 torchrun 下每 rank 独立 run_id
  文件：worldfoundry/cli/main.py
  改法：从 TORCHELASTIC_RUN_ID 或 MASTER_ADDR:PORT 派生；lifecycle 仅 rank0 写。

[T-08] P3 tests/training 用 skipif 而非 pytest.mark.gpu
[T-09] P3 --steps 输出加 steps_unit；manifest 记录 base_dir。

6. Studio 服务面（主会话补全）
------------------------------
serving/auth.py 对非回环 fail-closed 要求 WORLDFOUNDRY_STUDIO_AUTH_TOKEN，质量高，保持。
serving/http.py 的 path_allowed 限制静态根，ThreadingHTTPServer + backlog 可配，保持。

新建议（非攻击步骤，只谈运维默认值）：

[S-01] P2 network.get_external_ip 向 8.8.8.8:80 发 UDP 来猜出口 IP
  离线/禁网环境失败则回 127.0.0.1，但会制造意外外连。改为只在显式 --advertise-host 或已绑定非回环时使用，默认不探测。

[S-02] P2 workspace_app 仍用 app.add_event_handler("shutdown", ...)
  第 1 轮已 pin gradio<6；本轮补充：迁到 lifespan 后才能解 pin。可视化 _stop_all_visualizers 必须挂在进程退出路径上（含 SIGTERM），避免 world_explorer 子进程残留。

[S-03] P3 实时通道
  已有 WORLDFOUNDRY_REALTIME_WEBSOCKET_ONLY；文档写清 WebRTC 失败时的回退、消息体上限、心跳。
  daemon_threads=True 的产物 HTTP 服务在解释器退出时可能不等待传输完成——关闭顺序：先停生成作业，再停静态服务。

[S-04] P3 上传/作业
  查清 Gradio/FastAPI 上传默认上限并写成 WORLDFOUNDRY_STUDIO_MAX_UPLOAD_MB；与第 1 轮 MAX_JOBS 自适应一起做。

8. 验收标准
------------
- 设置 GEMINI_API_KEY 后跑 devil 官方 runner，scorecard.json 与 ps 命令行均无密钥明文。
- 故意打断 hf download 后，prepare_official_assets --skip-existing 不得跳过该目录。
- pip install 出的 wheel 上 worldfoundry-eval zoo models download --help 能工作或给出「实现已打进包」的路径，而不是 ImportError。
- train-reward-service 无 server.host 时监听 127.0.0.1。
- 对 single-device 训练发 SIGTERM，run.json 不为 running。
- dino_wm 默认配置在无 SLURM 的机器上不再尝试 sbatch h100。
