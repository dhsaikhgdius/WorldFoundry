3. Core I/O / process / serialization
-------------------------------------
已核对：``serialization.write_json`` 默认 atomic=True；``integrity`` 用于 training/engine。
orchestration 显式 ``atomic=False`` 出现在 contract、existing_results、model_benchmark、
model_benchmark_suite、plan、service 等。

[IO-01] P1 评测 orchestration 与训练 I/O 栈分裂
  问题：crash/kill 时 scorecard.json、manifest、index 可能半截；训练 manifest 已 fsync。
  文件：evaluation/tasks/execution/orchestration/{contract,existing_results,model_benchmark,
        model_benchmark_suite,plan,service}.py
  改法：批量去掉 ``atomic=False`` 或换 ``integrity.replace_json_atomic``（仅限 machine JSON）；
        长流 JSONL 用 JsonlWriter + 周期性 flush，终态文件 atomic 替换。
  验收：kill -9 写 half 文件后，读者 read_json 不抛 JSONDecodeError，或文件不存在。

[IO-02] P2 长跑 JSONL 写路径不统一
  问题：``existing_results`` 已用 ``JsonlWriter``；suite/benchmark 仍 ``write_jsonl(..., atomic=False)`` 全量 materialize。
  文件：orchestration/existing_results.py vs model_benchmark_suite.py
  改法：样本级 append 走 JsonlWriter；聚合/manifest 走 atomic write_json。
  验收：10k 行 existing-results 峰值内存不随样本线性翻倍。

[IO-03] P2 遗留非原子下载
  问题：``core/io/artifacts.py:download_file_from_url`` 虽删 partial，但无 validator/atomic rename；
        注释已指向 ``download_to_cache``。
  文件：core/io/artifacts.py；grep 调用方
  改法：调用方迁移；函数 deprecate 并转发 download_to_cache。
  验收：中断下载后 ``os.path.exists`` 不视为 ready。

[IO-04] P2 torchrun 子进程缺统一观测
  问题：``core/process.run_torchrun_module`` 用 ``subprocess.run(capture_output=True)``，
        无进程组终止、无 lifecycle JSONL、大 stdout 全进内存。
  文件：core/process.py
  改法：复用 ``run_logged_subprocess`` 或至少 ``start_new_session`` + 日志文件路径参数。
  验收：torchrun 超时后无 orphan worker；日志可在 stdout_path  tail。

[IO-05] P3 read_json / JSONL 全量读
  问题：``read_json`` 直接 ``read_text``；损坏文件错误信息差；大 JSONL ``load_serialized`` 一次读入。
  文件：core/io/serialization.py
  改法：JSONDecodeError 包装 path；超大 JSONL 文档推荐 iter_jsonl。
  验收：truncated JSON 报错含路径与 byte offset 提示。

[IO-06] P3 artifacts.py 命名
  问题：``worldfoundry/core/io/artifacts.py`` 主要是 depth/flow 可视化，非 artifact 持久化。
  改法：迁至 ``core/visualization/`` 或 ``core/io/visualization.py``，保留 re-export 一期。
  验收：新代码 import 路径文档化；无循环 import。


4. Reporting / preflight / manifest
-----------------------------------
来源：[reporting/preflight 云端子代理](bc-c951617b-ca8f-5aff-9a31-3dec073b1cd1) 深度评审 + 主会话核对。

[RP-01] P0 official-run 静默短路陈旧/错误 results
  问题：``benchmark_runner._run_official`` 只要 ``runtime_spec.results_path`` 存在即
        ``official_results_import``、returncode=0、跳过官方命令。``results_path`` 可来自
        ``benchmark_data_root`` 自动探测，候选含 ``annotations.json``（数据集标注，非模型结果）。
  文件：orchestration/benchmark_runner.py L294-320、L1062-1092
  改法：official-run 仅接受显式 results 来源；``results_path_source==benchmark_data_root`` 禁止短路；
        通用探测删 annotations；短路时 scorecard 写 ``imported_preexisting_results`` blocker。
  验收：data_root 预置 results.json 时 official-run 不短路（eval_core 回归）。

[RP-02] P0 runtime preflight 与执行链路脱节
  问题：``runtime_preflight.py`` 完整 fail-closed，但 ``run_model_benchmark`` 启动官方子进程前
        不调用；``service.py`` preflight 只验 catalog；``preflight_report.json`` 不进 manifest/scorecard artifacts。
  文件：orchestration/model_benchmark.py、runtime_preflight.py、service.py、cli/preflight.py
  改法：存在 ``runtime_profiles/official/<benchmark_id>.yaml`` 时自动 preflight 写
        ``preflight_report.json``；不 ready 则 fail-fast + failed scorecard；
        ``WORLDFOUNDRY_SKIP_PREFLIGHT=1`` 逃生阀；补 ``check_profile`` 单测。

[RP-03] P1 复现 profile 基建空转（延续 round2 [O-09]）
  问题：``reproduction_profiles/`` 目录不存在，``reproduce`` 子命令 KeyError；
        缺失时 ``reproduction_profile_summaries`` 静默空元组。
  文件：data/benchmarks/reproduction_profiles/（新建）、reproduction_profiles.py、service.py
  改法：check in 1–2 种子 profile；目录缺失给可操作错误；eval_core 遍历 profile 契约测试。

[RP-04] P1 model-benchmark summary 元数据成批 None
  问题：``model_benchmark.py`` summary ``started_at/finished_at/worldfoundry_version/run_fingerprint`` 全 None；
        run_index 对主力运行类型无法排序/审计。对照 existing_results 已完整填写。
  文件：orchestration/model_benchmark.py
  改法：记录 utc 时间戳；复用 ``build_version_context``/``build_run_fingerprint``；同步 run_manifest。

[RP-05] P1 environment.json 缺 torch/CUDA
  问题：``package_names=("worldfoundry","numpy","pandas")`` 三处硬编码；GPU 复现关键版本缺失。
  文件：run_manifest.py、model_benchmark.py、existing_results.py
  改法：共享 ``REPRODUCIBILITY_PACKAGES`` 常量；``build_environment`` 增 cuda 段（import 失败置 null）。

[RP-06] P2 reporting schema 无版本号、loader 硬拒绝
  问题：reporting 侧 ``worldfoundry-scorecard`` 等无 ``-vN``；orchestration 已有 v1/v2 惯例；
        ``load_run_summary`` 不认识 schema 则 raise，历史 run 不可读。
  文件：reporting/run_report.py、run_index.py、__init__ 各 SCHEMA_VERSION
  改法：统一 ``<name>-vN``；loader 设 ``SUPPORTED_SCHEMA_VERSIONS``；bump 配 fixture 迁移测试。

[RP-07] P2 standalone official runner 无 run_manifest；samples_ref 路径错
  问题：``official_runner.run_main`` 只写 scorecard+jsonl，无 environment 快照；
        scorecard.py L243 硬编码 ``metrics/per_sample.jsonl``，实际为 ``per_sample_scores.jsonl``。
  文件：framework/official_runner.py、reporting/scorecard.py
  改法：run_main 成功/失败均 ``write_run_manifest_artifacts``；samples_ref 参数化。

[RP-08] P2 终态 JSON atomic=False；index 遇坏 summary 整表失败
  问题：model_benchmark_run.json、summary.json、prepared_evaluation.json 显式 atomic=False；
        kill 留截断 JSON；``build_run_index`` 单坏文件 raise 而非记入 issues。
  文件：model_benchmark.py、service.py、reporting/run_index.py
  改法：终态小文件删 atomic=False；index 构建单条 parse 失败入 issues 继续。
  （与 [IO-01] 同根。）

[RP-09] P3 manifest_hash 含绝对路径，跨机不可比
  问题：manifest_hash 覆盖 resolve() 过的 artifacts/output_dir/cache_paths。
  文件：reporting/run_manifest.py
  改法：保留 manifest_hash（完整性）；新增 reproducibility_hash（排除 host-specific 字段）。

[RP-10] P3 _demo.py 随包发布；preflight REPO_ROOT=parents[5] pip 失效
  问题：reporting/_demo.py 打进 wheel；runtime_preflight REPO_ROOT 在 site-packages 无意义。
  改法：_demo 移 scripts/examples；REPO_ROOT 改 ``core.io.paths.project_root()`` + fallback cwd。


5. Official runner 框架
-----------------------
已核对：``evaluation/tasks/execution/framework/official_runner.py`` 提供 BenchRunnerConfig、
run_official_pipeline、``_is_fresh_result``；约 50 个 ``run_*_official_runner.py``。
phyfps 有 visual_chronometer 与 phyfps_bench_gen 两套自定义 main。

[OR-01] P1  runner 碎片化
  问题：每 bench 复制 CONFIG/Hooks/argparse；部分未调用 ``ors.run_main``，freshness/blocked 逻辑分叉。
  文件：runners/phyfps_bench_gen/run_*_official_runner.py 等
  改法：catalog 注册 ``BenchRunnerConfig`` + entrypoint module；CLI 统一 ``worldfoundry-eval benchmark official``。
  验收：新增 bench 只需 YAML + hooks 模块，不必新 argparse 文件。

[OR-02] P2 per_sample_scores.jsonl 恒空
  问题：``build_scorecard`` 总是 ``write_jsonl(per_sample_scores_path, [])``。
  文件：framework/official_runner.py:646-647
  改法：有 per-sample 数据的 bench 填 rows；否则不写文件或在 scorecard 标 ``per_sample_scores: null``。
  验收：downstream 不把空文件当「零样本」证据。

[OR-03] P2 freshness 仅 mtime
  问题：``_is_fresh_result`` 用 ``st_mtime >= run_started_wall - slack``；NFS 时钟 skew、
        touch 旧文件可误判 fresh。
  文件：official_runner.py ``_is_fresh_result``、``_RESULT_FRESHNESS_SLACK_SECONDS``
  改法：官方命令 stdout 写 ``.run_started`` marker；或 results 内嵌 ``generated_at`` ISO 校验。
  验收：预置旧 results.json，run-official 成功后 blocked 而非误采 stale。

[OR-04] P2 默认 timeout 7200 无 bench 级覆盖表
  问题：``build_common_parser`` default ``WORLDFOUNDRY_BENCHMARK_TIMEOUT`` 7200；
        轻量 normalizer-only bench 与 GPU judge bench 同默认。
  文件：official_runner.py；各 bench CONFIG
  改法：BenchRunnerConfig 增 ``default_timeout_seconds``；catalog 可声明。
  验收：normalizer-only runner 文档化短 timeout 示例。

[OR-05] P3 --run-fixture 与 assets 布局
  问题：fixture 路径约定 ``worldfoundry/data/benchmarks/assets/<benchmark-id>/`` 无统一校验器。
  文件：official_runner.py run_fixture 分支；data/benchmarks/assets/
  改法：preflight 式 ``validate_fixture_layout(benchmark_id)``；缺文件 blocked_reason 明确。
  验收：缺 sample_results.jsonl 时 scorecard status=blocked 且 reason 可读。


6. Docs / AGENTS / thirdparty
-----------------------------
已核对：``scripts/docs/build.sh`` 跑 ``npm ci``、``types:check``、``build``；
``Makefile docs-check`` 仅 ``cli --help`` + ``zoo benchmarks --json``。
``docs/fumadocs/package.json`` predev/prebuild 均 ``api:generate``。

[DE-01] P1 docs 门禁分裂
  问题：文档站真实 breakage（API symbol 漂移、TS 类型）不进 PR 必跑 gate。
  文件：Makefile docs-check；scripts/docs/build.sh
  改法：``docs-check`` 增加 ``cd docs/fumadocs && npm run api:check && npm run types:check``；
        完整 build 留 nightly 或 ``docs-check-full``。
  验收：故意删 SYMBOLS 一项后 ``make docs-check`` 失败。

[DE-02] P2 predev 冷启动慢
  问题：每次 ``npm run dev`` 全量 ``api:generate`` + mdx:generate。
  文件：docs/fumadocs/package.json；scripts/generate-python-api.py
  改法：generator 写 content hash；输入未变则 skip；``--check`` 模式已有，dev 复用。
  验收：无 Python API 变更时 predev <5s（除 next 本身）。

[DE-03] P2 dev bind 地址与 AGENTS 不一致
  问题：package.json ``dev`` 用 ``--hostname 0.0.0.0``；AGENTS.md 示例 ``127.0.0.1:8014``。
  文件：docs/fumadocs/package.json；AGENTS.md
  改法：默认 127.0.0.1；``dev:lan`` 脚本绑定 0.0.0.0；cloud 文档写 port-forward。
  验收：本地默认不监听 all interfaces。

[DE-04] P2 thirdparty flash-attention 孤儿 submodule
  问题：``.gitmodules`` 声明 ``thirdparty/flash-attention``，工作区未 init；与 round2 LFS 交叉。
  文件：.gitmodules；scripts/setup/*
  改法：要么 CI/submodule init 文档化，要么从 .gitmodules 移除并改 optional extra 说明。
  验收：fresh clone 行为与 README 一致，无「半存在」路径。

[DE-05] P3 API 文档 SYMBOLS 手工表
  问题：``generate-python-api.py`` SYMBOLS tuple 手工维护；新 public API 易漏。
  文件：docs/fumadocs/scripts/generate-python-api.py
  改法：从 ``evaluation.api.__all__`` 或 registry 自动生成候选 + CURATED 过滤；api:check 失败列 diff。
  验收：新增 evaluation.api 导出未手工登记时 api:check  WARN 或 FAIL。
