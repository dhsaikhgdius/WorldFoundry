========================================
日期：2026-08-25
性质：建议修改（本文件只记录计划，不直接改代码）
承接：plan/infra_optimization_plan.txt（第 1 轮：Docker / CI / 安装 / GPU 集群）
续篇：plan/infra_optimization_plan_round3.txt（训练启动、下载流水线、密钥/CLI/scripts）
方法：主会话编排 + 4 个云端子代理并行评审（模型 claude-fable-5-thinking-xhigh）
  - Git/LFS/submodule、sdist/wheel 卫生、vendored 体积

  - 评测编排、generation cache、scorecard、existing-results

0. 现状一句话
--------------
第 1 轮解决的是「怎么装、怎么跑、怎么进 CI」；第 2 轮解决的是「装完之后
仓库/包/配置/评测结果是否可发布、可复现、可治理」。当前最大缺口：
pip wheel 把 200MB+ 无关资产打进去、catalog 引用校验空转、reproduce CLI
没有 profile、official-run 会被旧 results.json 静默短路。


1. 不建议改的地方
------------------
- 不要把 thirdparty/gsplat、kairos_fla、SageAttention 改成 submodule 集合：它们带本地补丁，应做的是不进 sdist。
- 不要靠继续加 packages.find.exclude 来瘦 wheel：实测 include-package-data + setuptools-scm file-finder 会打穿包排除；收口点是 exclude-package-data / MANIFEST.in。
- 不要现在 git rm test_cases 存量文件：不缩小 .git 历史，还会弄坏 CPU 测试引用。外置必须和 history rewrite 一起做。
- 不要给 native-kernels 套 setuptools-scm：子目录 scm 根会指到仓库根；硬编码版本 + extra 约束更稳。
- 不要软化 native loader 的 torch 版本等值匹配与 poison 语义。
- 不要外置 13MB in-tree official runner 运行时：离线可复现优先于包体积。
- 不要动 core/io/serialization.py 原子写、run_logged_subprocess 进程组终止、training/distributed/parallel.py（torchrun own-or-validate）。
- 不要动 generate-python-api.py 的 ast-only 设计（docs 构建零 worldfoundry 依赖）。
- 不要动 schema.py 别名归一化表（兼容层）；冻结新增、清洗数据后再收缩。
- 不要改 catalog→runtime profile 的覆盖合并方向。
- 不要把 readme-demos / cover_4x4_hero.mp4 改回 LFS（GitHub README 原生渲染需要原始文件）。
- 第 1 轮已划的边界继续有效（ruff 0.12.7、allenai 官方镜像、不要一次 xfail eval-core）。

3. Git / LFS / 打包 / 仓卫生
----------------------------
现状（第 2 轮子代理实测 python -m build）
  工作树约 586 MB，其中 data/test_cases 338 MB；.git pack 约 460 MB。
  普通 blob 媒体约 423 MB / 1380 文件（不走 LFS）；LFS 109 个对象约 4.4 GB，全在 docs/fumadocs/public/。
  sdist 约 82 MB（含 plan/、三套测试树、docs、thirdparty/gsplat 等）；wheel 约 73 MB 压缩 / 203 MB 解压。
  packages.find.exclude 排掉的 *_runtime 仍以 package-data 进 wheel（34 个 __init__.py 可 import）。
  .gitmodules 声明 thirdparty/flash-attention，HEAD 无 gitlink，submodule update 失败。
  git tag 为空，setuptools-scm 版本恒为 0.1.devN；无 fallback_version 时无 .git 的 tarball 安装失败。

建议修改

[P-01] P1 大文件闸门与 LFS 错配
  文件：.pre-commit-config.yaml 、 .gitattributes 、 新增 .lfsconfig
  现状：*.bin/*.pt/*.pth 等 LFS 规则匹配 0 文件；真实大文件是 pkl/json/npy/exr；
        docs 演示 mp4 走 LFS 共 4.4 GB，无 fetchexclude。
  改法：pre-commit-hooks 加 check-added-large-files --maxkb=2048；
        .lfsconfig：[lfs] fetchexclude = docs/fumadocs/public/demos/** ；
        LFS 规则改为按路径圈定 docs 演示，而不是按扩展名全仓拦截。
  中期：demo 视频迁 GitHub Release / CDN；test_cases 迁 HF dataset + 下载清单，再 filter-repo。

[P-02] P2 孤儿 submodule
  文件：.gitmodules 、 thirdparty/README.md
  改法：删除 flash-attention 条目（文件可整删）；README 改为说明 flash-attn 走 pip。

[P-03] P1 wheel/sdist 膨胀
  文件：pyproject.toml [tool.setuptools.exclude-package-data] 、 MANIFEST.in
  改法：exclude 增加 **/eigen/** 、 **/tests/** 、 yolo_world/data/** ；
        world_explorer package-data 收窄为 *.py 入口，不要 native/world_explorer/**/* ；
        MANIFEST prune plan tests test test_stream docs packages ，并补 prune thirdparty/{gsplat,kairos_fla,SageAttention}。
  验收：重新 python -m build，wheel 目标 <20 MB 量级（核心 CLI 用户不该下载 Eigen 与 35 MB lvis json）。

[P-04] P2 悬空 logo 与 ignore 陷阱
  文件：pyproject.toml package-data 、 .gitignore 、 worldfoundry/cli/tui_brand.py
  现状：package-data 声明 openenvision_logo.png，但 .gitignore 忽略 worldfoundry/cli/assets/*.png，git 未追踪。
  改法：git add -f 提交并加 negate 规则，或删 package-data 行并让 TUI 优雅降级。

[P-05] P2 setuptools-scm
  文件：pyproject.toml [tool.setuptools_scm]
  改法：fallback_version = "0.0.0.dev0"；打第一个 tag（如 v0.1.0a1）。

[P-06] P2 许可证声明缺口
  若 Eigen/nlohmann json/stb 仍进 wheel：THIRD-PARTY-NOTICES 补 MPL-2.0 / MIT 条目。优先按 P-03 移出 wheel。

[P-07] P3 治理文件

5. 评测编排 / cache / scorecard
--------------------------------
现状
  编排分层清晰：CLI 意图 → service → evaluate → contract/existing_results → cache。
  缓存键含 git commit + dirty 布尔 + 模型指纹，方向正确；SQLite 无 WAL、无 GC、get_many 读路径含写 hits。
  DEFAULT_REPRODUCTION_PROFILE_ROOT 指向不存在的 worldfoundry/data/benchmarks/reproduction_profiles/。
  _run_official：只要 runtime_spec.results_path 文件存在就 status=official_results_import、returncode=0、不跑命令——官方跑也会被 data_root 里旧 results.json 短路（scorecard 里 official_benchmark_verified=False，但仍是「成功」）。

建议修改

[E-01] P0 reproduce 开箱即死
  新建 worldfoundry/data/benchmarks/reproduction_profiles/ 并提交至少一个真实 profile；
  或 reproduction_profile_summaries 对缺失根打 WARN，CLI help 写明当前无内置 recipe。禁止静默空元组再 KeyError。

[E-02] P0 official-run 探测短路
  文件：worldfoundry/evaluation/tasks/execution/orchestration/benchmark_runner.py _run_official
  改法：mode == official-run 且 results_path_source == "benchmark_data_root" 时不得 import 短路；
        import 仅接受显式 --official-results-path；scorecard run.status 保持 official_results_import 显著标记。

[E-03] P1 SQLite 并发
  文件：worldfoundry/evaluation/tasks/execution/orchestration/cache.py
  改法：PRAGMA journal_mode=WAL; busy_timeout=30000; synchronous=NORMAL；
        get_many 的 hits 更新改为尽力而为，失败不影响读。

[E-04] P1 缓存键正确性
  文件：worldfoundry/evaluation/utils.py git_metadata / build_version_context
  改法：dirty 时加入 git diff 内容哈希（dirty_diff_sha256），不要只用 dirty=True 布尔；
        从键中移除 python.executable（换 venv 不应全量 miss）。
  注意：与 E-07 一起 bump version_context schema，一次性失效旧缓存。

[E-05] P1 无 GC / 惊群
  cache.py 增加 prune(max_age_days / max_rows / max_bytes)，CLI worldfoundry-eval cache prune；
  audit.jsonl 轮转或采样；miss 后按 key_hash 文件锁 single-flight，拿不到锁则等待再二次查找。

[E-06] P2 路径可移植

[E-08] P2 官方子进程默认超时
  文件：benchmark_runner.py
  改法：env WORLDFOUNDRY_BENCHMARK_TIMEOUT_SECONDS，缺省若干小时；终止语义向 core/process.run_logged_subprocess 收敛。

[E-09] P2 cache schema 读侧校验
