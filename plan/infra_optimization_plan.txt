0. 现状一句话
--------------
仓库已有 conda 统一 GPU 环境、CUDA tier 探测、Studio 设备租约、评测 CLI 门禁雏形，
但四条基建链路彼此脱节：基座 Docker 镜像无人消费、CI 两个 job 在 main 上均红、
安装脚本默认走 GPU 全量且无 lockfile、集群/评测容器靠硬编码与 :latest。


1. 不建议改的地方（先划边界）
------------------------------
- environment.yml 瘦 + pip 层胖：conda 只管系统件（ffmpeg/eigen/nvcc），torch 走 wheel index。不要合成单一 conda YAML。
- model_env_install.sh 的专用 env：部分模型确有硬 ABI pin，隔离机制保留；只修黑名单矛盾。
- packages/worldfoundry-native-kernels 独立包 + 禁 build isolation：ABI 契约正确，不要并入主 wheel、不要发通用 PyPI 二进制。
- test/conftest.py 的 collect_ignore：44 个顶层 demo 脚本继续排除，不要改造成 CI 测试。
- ruff==0.12.7：Makefile / pre-commit / AGENTS.md 三处对齐；升级会改 import-sort 输出。CI 建议改成 == 而不是放宽。
- ruff 白名单（RUFF_SOURCES）本次不要扩张到 core/training：那是内容治理，会淹没门禁修绿。
- 不要一次性 xfail/删除 eval-core 里大量契约失败：用 allow-failure 分层，按契约域分批修。
- 不要把 allenai vla-evaluation-harness 换成自建镜像：official parity 依赖它们；治理点是 digest/mirror，不是镜像内容。
- 不要现在把源码 COPY 进基座做全量 release 镜像：flash-attn 与 CUDA tier 是运行时决策。
- 不要给当前 bash 基座加 HEALTHCHECK / 强推 non-root：无守护进程；评测需要写挂载卷。
- runtime/jobs.py 进程组终止链、local_checkpoint_cache 的 rank0+flock、compile_cache 指纹设计、studio/serving/auth.py fail-closed：质量高，只补缺口。
- platforms/ 的 Protocol 探测层不要为「多云」提前重写；真正的单云问题在 DLC bash 脚本。
- vendored mmyolo Dockerfile：标注非支持路径即可，不要改上游 diff。
- 不要在 CI 装 [all] extra 或 GPU 依赖。


2. 优先级实施顺序（建议按此落地）
--------------------------------
P0 止血（改动小、立刻改善正确性/可用性）
  1) pin [ui] extra 的 gradio/starlette（裸装 Studio 即碎）
  2) ruff --fix 修掉现有 8 个 lint，让 public-surface 能绿
  3) CI eval-core 补齐 CPU torch + 隐式依赖；收集漂移修 1 处 import
  4) conda 第二段 pip 加 torch 三件套 constraint，防止 xformers 偷换 CUDA 构建
  5) CUDA_DEVICE_ORDER=PCI_BUS_ID（或 GPU UUID 作为租约 token）
  6) DLC 脚本去掉账户级硬编码默认值；job 名用 config-id

P1 可复现与门禁分层
  7) 分 CUDA tier 的 lockfile + git 依赖 pin commit + CI dry-run 防漂移
  8) cu121/cu124 与 torch>=2.7 矩阵对齐（修上限或下线旧 tier）
  9) CPU 主机默认不再走 cu128+强制 flash-attn 源码编译
 10) CI 拆 docs-build / python-quality；miniconda 换成 setup-python + pip cache
 11) eval-core 全量 continue-on-error + 绿色子集硬门禁；新增 training-tests job
 12) embodied 评测镜像 :latest → digest；mirror 保真

P2 入口收敛与隔离
 13) 删除 conda_profile_install.sh 与被忽略的 legacy flags；preset slim 要么真 slim 要么删
 14) docker build 去掉 host network；push 默认只 amd64；CI 加 docker-smoke
 15) docker_runner 加 shm/init/超时/只读挂载；model_server 默认 127.0.0.1 + 非回环鉴权
 16) 作业落盘 job.json + 崩溃孤儿对账

P3 约定统一与清理
 17) checkpoint 三套布局收敛、GC、size 校验
 18) WORLDFOUNDRY_* 路径默认统一；脚本默认产物离开仓库 tmp/
 19) extras 去重、README 双轨安装文档、native-kernels 可选安装
 20) dependabot、actions SHA pin、compile_cache --gc、Studio 并发按 GPU 自适应


3. Docker / 镜像 / 构建
------------------------
现状
  docker/Dockerfile 只做 CUDA devel 基座 + apt + uv，不装 worldfoundry、不 COPY 源码。
  docker/build_with_docker.sh 无条件 --allow network.host --network host；--push 默认 linux/amd64,linux/arm64。
  全仓无消费者：test/run_tests_docker.sh 默认仍用裸 nvidia/cuda:12.8.1-cudnn-devel-ubuntu22.04，并重复一份 apt 清单。
  embodied 评测走另一套：runtime profile 的 ghcr.io/allenai/...:latest，经 scripts/embodied/mirror_docker_images.py 搬运。
  CI 零 docker 覆盖；make shell-check 只 lint scripts/setup。

建议修改

[D-01] P1 评测镜像全部 :latest，mirror 丢 digest
  文件：worldfoundry/data/benchmarks/runtime_profiles/official/*.yaml
        scripts/embodied/mirror_docker_images.py
        worldfoundry/evaluation/tasks/embodied/docker_runner.py
  改法：mirror 改 docker buildx imagetools create 或 skopeo copy --all，写出 source digest 映射 JSON；
        profile 增加 docker.digest 或直接用 @sha256:...；_ensure_image pull 后校验。

[D-02] P1 构建脚本硬编码 host network
  文件：docker/build_with_docker.sh
  改法：删除 --allow network.host --network host；如需内网代理用 WORLDFOUNDRY_DOCKER_NETWORK 显式 opt-in。
  原因：该 Dockerfile 不需要 host 网络；docker-container driver 未开 entitlement 时多架构 push 开箱即坏。

[D-03] P2 push 默认 arm64 对本栈不现实
  文件：docker/build_with_docker.sh
  改法：默认 linux/amd64；arm64 仅 --platform 显式开启。
  原因：xformers/gsplat/flash-attn/pipablepytorch3d 无可用 aarch64 CUDA wheel。

[D-04] P1 基座镜像是孤儿，apt 清单双份维护
  文件：test/run_tests_docker.sh 、 docker/Dockerfile
  改法：测试脚本默认镜像改为发布后的 ghcr.io/openenvision/worldfoundry:base（保留 env 回退）。

[D-05] P2 uv/Python 不 pin，镜像 Python 3.10 vs environment.yml 3.11
  文件：docker/Dockerfile 、 test/run_tests_docker.sh
  改法：uv 改固定 tag（不要 :latest，不要 curl | sh 无版本）；容器 Python 对齐 3.11。

[D-06] P2 .dockerignore 根锚定导致多数模式失效
  文件：.dockerignore
  改法：裸 data/ cache/ *.mp4 *.ckpt 等改为 **/ 前缀；显式忽略 worldfoundry/data/test_cases/、thirdparty/、plan/、docs/。
  备注：当前 Dockerfile 无 COPY，问题潜伏；一旦 COPY . . 会把约 400MB test_cases 打进上下文。
  另：忽略 .git 后 setuptools-scm 动态版本需要 SETUPTOOLS_SCM_PRETEND_VERSION，加注释。

[D-07] P2 缺 runtime / CPU 瘦镜像
  文件：docker/Dockerfile
  改法：多 stage：base-runtime（cudnn-runtime + 最小 apt）与现有 base-devel；CPU CI 可用 python:3.11-slim。
  devel 保留（flash-attn 需要 nvcc），但不应是唯一选项。不要为 cu121/cu124 各出一份基座。

[D-08] P1 CI 无 docker 冒烟
  文件：.github/workflows/ci.yml 、 Makefile
  改法：paths 过滤 docker/** 时跑 hadolint + amd64 build（不 push）；shell-check 扩到 docker/ scripts/embodied/ test/*.sh。

[D-09] P2 docker_runner 隔离弱
  文件：worldfoundry/evaluation/tasks/embodied/docker_runner.py
  现状：--network host 写死；仓库读写挂载；PYTHONPATH 含不存在的 /workspace/WorldFoundry/src；gpus 默认 all；无 --shm-size/--init；无超时。
  改法：network/gpus/shm 进配置（默认保持兼容，因 model_server 走 ws://127.0.0.1）；仓库挂载 :ro；删 /src；
        默认 --shm-size（可配，如 8g）与 --init；存在 CUDA_VISIBLE_DEVICES 时透传而非 all；
        用 run_bounded_command 包超时；--name 加 eval_id 后缀。

[D-10] P3 Dockerfile 卫生
  删冗余 mkdir / bash；加 OCI LABEL org.opencontainers.image.source；交互工具（nano/tmux/ping）移到 dev stage。

[D-11] P3 run_tests_docker.sh 挂整份 ~/.netrc
  改法：改为 -e HF_TOKEN；netrc 仅 WORLDFOUNDRY_MOUNT_NETRC=1 时挂载。

5. 安装 / conda / extras / 锁定
--------------------------------
现状
  五层 bash：setup.sh → bootstrap_worldfoundry.sh → unified_install.sh → conda_install.sh → install_flash_attn.sh。
  conda_profile_install.sh 全仓无引用；它转发的 --pytorch-bundle/--transformers/--three-d-core 在 conda_install.sh 里被丢弃。
  preset max-infer 与 slim 装同一份 requirements/worldfoundry-unified.txt。
  无任何 lockfile；Docker 装了 uv 但仓库从不 uv lock。
  默认 TORCH_SPEC=torch>=2.7,<2.12.0，但官方 cu121 index 最高 2.5.1、cu124 最高 2.6.0；
  pip 会经 --extra-index-url 静默从 PyPI 拉错 CUDA 变体。
  第二段 pip 只用 pypi.org，未 pin 的 xformers/torchao 可能重装 torch 覆盖 cu-index 版本。
  [ui] extra 的 gradio 未 pin；workspace_app.py 仍用 app.add_event_handler，gradio 6 / starlette>=1 会启动失败（AGENTS.md 已记录）。
  无 GPU 时 auto 仍返回 cu128，且默认源码编译 flash-attn，验证阶段再因无 CUDA 退出。
  flash-attn：FORCE_BUILD + --no-binary，bucket 参数不参与安装；CUDA_HOME 默认 /usr/local/cuda，绕过 conda 刚装的 nvcc。
  checkpoint 默认路径至少四种：installer 的 HOME/models/checkpoints、env.py 的 HOME/checkpoints、
  paths.py 的 cache/checkpoints 或 ../ckpt 魔法、Makefile 的 ~/.cache/worldfoundry/checkpoints/hfd。

6. 运行时 / GPU / 作业 / 集群
------------------------------
现状
  device_pool.CudaDeviceLeasePool 是进程内内存池；conda_dispatch 把 nvidia-smi index 写入 CUDA_VISIBLE_DEVICES，
  从未 set CUDA_DEVICE_ORDER（默认 FASTEST_FIRST ≠ PCI 顺序）。
  jobs.py / StudioJobStore 作业全在内存；崩溃后子进程组可继续占 GPU，无 pid 对账。
  checkpoint 下载三条路径三种布局（hfd 直下、HF hub cache、ckpt/hfd_models），无 sha256、无 GC。
  DLC 脚本默认 DLC_BIN=/etc/dsw/runtime/export_bin/dlc，job 名 sft_innovator_science_data，
  账户 resource/workspace/vpc/sg/cidr 写死；镜像密码走 argv。
  embodied model_server 默认 0.0.0.0 且无 token；Studio serving 已有 fail-closed 鉴权可作模板。
  Studio MAX_JOBS 默认 8，常驻 worker 上限跟随；无 GPU 云主机不安全。
  多个脚本默认写仓库 tmp/，与 WORLDFOUNDRY_ARTIFACT_DIR 规范并存。
  studio/runtime_paths.py 硬编码 /share/project ↔ /bench-workspace。

8. 验收标准（落地时）
--------------------
- make lint 在 main 上绿；pre-commit run -a 不再因 lint 必红。
- CI python-quality 绿；eval-core 至少有一个非空的硬门禁子集持续绿。
- pip install -e ".[ui]" 能启动 Studio（不再因 add_event_handler 崩溃）。
- --cuda cu121/cu124 要么装到匹配 CUDA 的 torch，要么明确拒绝，禁止静默 PyPI 回退。
- 无 GPU 机器跑 setup.sh 得到可理解的 CPU 路径，而不是编译 flash-attn 数小时后失败。
- docker buildx build -f docker/Dockerfile . 在干净 Docker 上不需要 network.host entitlement。
- 公开默认值中不再出现具体阿里云 VPC/配额 ID；DLC 缺配置时本地失败而不是提交到他人资源。
- 评测 official profile 至少对一条 benchmark 绑定 digest，重复跑镜像内容不变。
- conda_dispatch 子进程的 CUDA_VISIBLE_DEVICES 与 nvidia-smi PCI 顺序一致（或改用 UUID）。


9. 风险与拆分建议
----------------
- 不要把本计划做成一个巨型 PR。按第 2 节 P0 → P1 → P2 拆。
- P0 的 ruff --fix 与 pin gradio 互不阻塞，可并行。
- eval-core 444 量级契约失败属于目录/内容问题，不要塞进 infra PR。
- lockfile 会让 requirements 评审变大，单独 PR，并先只锁 cu128。
- DLC 去硬编码是行为变化：内部用户必须改设 env；PR 说明里写迁移清单。
- digest 固定评测镜像会让「自动跟随 upstream latest」变成显式 bump，这是期望行为。
