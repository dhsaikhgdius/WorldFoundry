This page is the quick-reference index of the repository: one row per top-level package, what it owns, and the first file to read. It is deliberately compact. For the *why* behind these boundaries, read [Architecture](/docs/maintainers/architecture) and the subpages it links to. Use this map to decide *where* a change belongs before opening a file.

The boundary rule is the same on every row: a package exposes stable, serializable contracts to its neighbors and keeps private details inside. Cross-package edges that skip the contract layer (for example, a benchmark importing a pipeline, or a pipeline importing an evaluator) are the bugs to look for here.

## Repository layout

| Package | Owns | First file to read |
| --- | --- | --- |
| `worldfoundry/cli` | User-facing commands: TUI, evaluate, embodied, run, validate, zoo, preflight, reporting. Dispatches into orchestration, never owns model inference or scoring. | `cli/main.py:1580` `main()`; subcommand tree at `cli/main.py:1091` |
| `worldfoundry/cli/tui*.py` | Guided-discovery TUI surfaces (discovery, brand, app). | `cli/tui.py`, `cli/tui_app.py` |
| `worldfoundry/mcp` | MCP server and tools (discovery, metrics, readiness, context) reused from the same catalog/runtime contracts. | `mcp/__init__.py:30` `main()`; `mcp/tools/registration.py:47` `register_tools` |
| `worldfoundry/runtime` | Execution environment preparation: conda profiles, device pool, CUDA tiers, compile cache, in-tree CLI bridges, asset staging. | `runtime/conda.py`, `runtime/env.py`, `runtime/cuda_tiers.py` |
| `worldfoundry/data` | Catalogs, runtime profiles, benchmark tasks, and test fixtures. Declares what exists and what is ready; not runtime behavior. | `data/models/catalog/`, `data/benchmarks/catalog/`, `data/models/runtime/profiles/` |
| `worldfoundry/core` | Shared inference infrastructure: loading, attention, distributed, VRAM, kernels, memory, configuration, IO, safety. The only home for offload/distributed/kernel/quantization. | [Core infrastructure](/docs/maintainers/architecture/core-infrastructure) |
| `worldfoundry/base_models` | Inference-only model packages: `diffusion_model` (the single canonical diffusion kernel), `llm_mllm_core`, `perception_core`, `three_dimensions`. | `worldfoundry/pipelines` | One thin public wrapper per model family: `from_pretrained`, `process`/`__call__`, optional `stream`. | `pipelines/pipeline_utils.py:11` `PipelineABC`; 88 family dirs under `pipelines/` |
| `worldfoundry/operators` | Input-side partners for runnable pipelines: validation, media loading, camera/action parsing, interaction shaping, perception preprocessing. | `operators/base_operator.py:4` `BaseOperator` |
| `worldfoundry/synthesis` | In-tree runtime execution: hosted API wrappers, native runtime bridges, per-family `synthesis.py`, action surfaces, memory modules. | `synthesis/base_synthesis.py:38` `BaseSynthesis`; [Runtime assembly](/docs/maintainers/architecture/runtime-assembly) |
| `worldfoundry/representations` | Converts model outputs into geometric/world artifacts: depth, point clouds, 3DGS, panorama, geometry assets. | `representations/base_representation.py:4` `BaseRepresentation` |

## How the rows connect

A run flows down the table, not across it at random. User input enters through `cli` or `mcp`; `runtime` and `data` prepare the environment and declare what can run; `core` and `base_models` provide the shared inference primitives; `pipelines` plus `operators` plus `synthesis` turn a normalized request into a `GenerationResult`; `representations` derives geometric artifacts when needed; `evaluation` consumes artifacts and produces scorecards; `studio` previews the same artifacts through a UI shell.

<Callout type="info">
  The package a file lives in should answer "who owns this kind of change?" before you read the code. If you are unsure which layer owns a fix, start at [Architecture](/docs/maintainers/architecture) and pick the subpage that matches the layer you are changing.
</Callout>

## Where to go next

- **Adding a model** — start at `pipelines/` and `operators/`, then `synthesis/`. See [Model runtime](/docs/maintainers/architecture/model-runtime) and [Runtime assembly](/docs/maintainers/architecture/runtime-assembly).
- **Adding a benchmark** — start at `data/benchmarks/` and `evaluation/tasks/`. See [Benchmarks and data](/docs/maintainers/architecture/benchmarks-data) and [Evaluation core](/docs/maintainers/architecture/evaluation-core).
- **Tracing a run** — start at `cli/main.py` → `evaluation/tasks/execution/orchestration/`. See [Workflow](/docs/maintainers/architecture/workflow) and [Surfaces and orchestration](/docs/maintainers/architecture/surfaces-orchestration).
- **Shared primitives** — anything reusable across model families belongs in `worldfoundry/core`. See [Core infrastructure](/docs/maintainers/architecture/core-infrastructure).
