## Why this layer exists

`worldfoundry/core` is the shared inference infrastructure that every model family reuses and none of them owns. Checkpoint loading, state-dict remapping, attention backends, distributed collectives, VRAM placement and offload, kernels, configuration, media IO, memory contracts, and safety guardrails all live here once. A family package (`worldfoundry/base_models/*`, `worldfoundry/synthesis/*`, `worldfoundry/pipelines/*`) composes these primitives; it must not recreate them.

This is the layer to read when you are about to copy a utility into a model directory. The rule is explicit: if a capability can serve more than one family, it belongs in `core` first. See [Native diffusion](/docs/maintainers/architecture/native-diffusion) for how diffusion consumes this layer, and [Model runtime](/docs/maintainers/architecture/model-runtime) for how pipelines and operators do.

## Dependency rule

`core` may depend on PyTorch, `diffusers` model/operator primitives, and narrow third-party libraries. It must not import `worldfoundry.pipelines`, `worldfoundry.synthesis`, `worldfoundry.operators`, `worldfoundry.representations`, `worldfoundry.base_models` family packages, or `worldfoundry.evaluation`. The edge points *out of* family packages *into* `core`, never the reverse.

This keeps family packages thin: a model directory contains checkpoint-compatible tensor math and contract adapters, not a second copy of an offload manager, a distributed bootstrap, a kernel registry, or a quantization system. When you find yourself adding one of those to a family package, move it to `core` first and import it from there.

<Callout type="info">
  The diffusion package restates this rule for its own boundary in [Native diffusion](/docs/maintainers/architecture/native-diffusion). Generic attention, transformer, loading, and offload primitives live in `core`; diffusion-domain contracts, schedulers, and recipes live in `base_models/diffusion_model`.
</Callout>

## Where it is consumed

- **Diffusion** — `base_models/diffusion_model` loads checkpoints through `core/model_loading`, runs attention through `core/attention`, and offloads through `core/vram`. Its `optimizations/` re-exports core policy, not a parallel implementation.
- **Hosted and native runtimes** — `synthesis/` stages inputs through `core/io` and writes artifacts through the same media helpers.
- **Memory** — `core/memory/base.py` defines the contract; streaming and long-context state in `synthesis/*/memory` and action-policy trace state in `synthesis/action_generation/memory.py` implement it.
- **Distributed execution** — `core/distributed` is the only place model-parallel groups are initialized; no family package boots its own NCCL group.

## What does not belong here

Training entrypoints, datasets, dataloaders, losses, callbacks, augmentation-only modules, and experiment scripts do not belong in `core`, nor in `base_models`. `core` is inference infrastructure; if a module only matters during training, it should not be added here.

For the directory-level map of every package, see [Codebase map](/docs/maintainers/architecture/file-index). For how a model call flows through these primitives, see [Model runtime](/docs/maintainers/architecture/model-runtime) and [Runtime assembly](/docs/maintainers/architecture/runtime-assembly).
