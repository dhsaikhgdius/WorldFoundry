本页是仓库的速查索引：每个顶层包一行，说明它拥有什么、第一个该读的文件是哪个。内容刻意保持精简。要理解这些边界的*原因*，请读 [架构](/zh/docs/maintainers/architecture) 及其链接的子页。在打开文件之前，先用本页判断改动*应当落在哪一层*。

每一行的边界规则都相同：一个包向邻居暴露稳定、可序列化的契约，私有细节留在包内。绕过契约层直接跨包引用（例如 benchmark 直接 import pipeline，或 pipeline 直接 import evaluator）就是本页要帮你定位的 bug。

## 各行如何衔接

一次 run 是顺着表格向下流动，而不是随机横向引用。用户输入经 `cli` 或 `mcp` 进入；`runtime` 与 `data` 准备环境并声明可运行项；`core` 与 `base_models` 提供共享推理原语；`pipelines` 加 `operators` 加 `synthesis` 把归一化 request 变成 `GenerationResult`；需要时 `representations` 产出几何 artifact；`evaluation` 消费 artifact 产出 scorecard；`studio` 通过 UI 壳预览同一 artifact。

<Callout type="info">
  一个文件所在的包应当在你读代码之前就回答“这一类改动归谁”。如果不确定某修复属于哪一层，从 [架构](/zh/docs/maintainers/architecture) 起步，选择与你要改的层匹配的子页。
</Callout>
