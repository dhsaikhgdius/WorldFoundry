WorldFoundry 是一套**运行与评测世界模型的开源基础设施**。它不是又一个模型架构，而是把模型发现、runtime 准备、推理、artifact 检查、benchmark 执行与证据报告连成一条工作流，覆盖视频、3D/4D、交互式世界与具身系统：

> 发现模型，准备 runtime 与资产，生成可检查的 artifact，评测 artifact，再把结果保留为可审查证据。

这个区别很重要。模型被 catalog 收录，不等于它的 runtime 可以跑；demo 效果好，不等于已经形成 benchmark 证据；分数导入成功，也不等于达到了官方 leaderboard 水平。WorldFoundry 把这些状态分开记录，并明确展示。

<GithubInfo locale="zh-CN" />

它要解决的问题很实际：每个上游项目都能产出有价值的结果，但各自带着不同的环境、checkpoint、输入、启动命令、输出 layout 与评测 protocol。WorldFoundry 保留这些原生差异，同时统一它们周围的系统边界。

## 它解决的问题

世界模型项目通常以彼此独立的仓库发布，各自定义环境、checkpoint、输入格式、启动脚本、输出目录、预览工具和评测代码。团队要比较多个系统时，往往得为每个模型重复搭一遍同样的集成层。

碎片化从发现阶段就开始了。同一个模型可能同时有论文名、仓库名、checkpoint 名和本地目录名。WorldFoundry 为模型与 benchmark 提供稳定 ID 和声明式 manifest，在跑昂贵任务之前就能看清来源、预期能力、runtime binding、所需资产与已知 blocker。

碎片化在执行阶段继续。WorldFoundry 不再把 checkpoint 和 dataset 散落到各个上游脚本碰巧约定的目录，而是定义可复用的本地资产根目录与模型专属 runtime profile。Pipeline 和 operator 保留模型的原生差异，同时向系统其余部分提供统一的 request、result 与 artifact 边界。

到了评测阶段，最容易丢失的是证据。视频、mesh、动作和 trace 不该消失在临时目录或一次性 notebook 里。WorldFoundry 会记录请求了什么、实际跑了什么、产出了什么、怎么打的分、覆盖了哪些 sample，以及还有哪些条件挡着官方声明。

它的目标不是用一个极小的 API 抹平所有模型差异，而是把差异放回该在的那一层，同时让端到端的研究工作流保持一致。

## 项目怎样工作

<WorldFoundryWorkflow locale="zh" />

整个设计的核心边界是 **artifact**。模型 runner 把归一化 request 转成 result——视频、几何、动作 trace 或其他输出；benchmark runner 消费这些输出，产出 metric 与证据。有了这层分离，同一份模型输出可以先人工检查，再交给多个兼容 benchmark 打分，而模型实现不必耦合 evaluator 的内部逻辑。

Catalog 构成这条边界周围的控制平面。它描述系统中有什么、来自哪里、需要什么、如何调度，以及哪些证据支撑当前 readiness。TUI、CLI、Studio、Python 与 MCP 是操作同一套底层系统的五种方式，不是五套彼此独立的实现。

### 一个具体 run：Matrix-Game 2

第一次运行 `matrix-game-2` 时，先让 catalog 与本地资产检查确认“选中的是哪个模型、checkpoint 是否就绪”，再生成一个小结果：

```bash
bash scripts/inference/prepare_model_infer.sh matrix-game-2 --download
python -m worldfoundry.evaluation zoo model-download \
  --model-id matrix-game-2 --check-local --json

bash scripts/inference/test_nav_video_gen.sh matrix-game-2 \
  --output-dir tmp/matrix_game2_first_run
```

最后一条命令用动作条件输入运行模型，把视频和相关运行记录写入指定目录。此时能成立的只有一个结论：这套配置产出了可检查的 artifact。运动与连贯性可以在 Studio 或本地播放器中检查，兼容的 metric 也可以消费这份 artifact。但仅凭一段视频，仍不能说明某个 benchmark 已完整跑通——这正是 WorldFoundry 把生成、检查、评分与资格判断拆开的原因。
