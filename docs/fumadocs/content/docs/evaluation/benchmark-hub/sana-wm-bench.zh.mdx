## 评测目标

SANA-WM Bench 是 NVIDIA 随 Sana 项目发布的公开基准，面向分钟级、相机可控的世界模型视频生成。它在两个 60 秒相机轨迹划分（`simple_60s` 与 `hard_60s`）下评测 80 个固定首帧场景。每条轨迹为 961 帧、16 FPS。模型接收首帧图像、文本 prompt 和完整相机轨迹，需要生成沿该轨迹的 60 秒视频。

WorldFoundry 以树内组合式评测器的形式集成该基准：基准专属的数据布局、prompt 绑定、重访帧对协议、时间窗口聚合与 scorecard 契约都在本仓库内实现。runner 刻意复用 WorldFoundry 常驻的 VBench 与 Pi3 模型表面，评测时不会执行 NVlabs/Sana 的外部 checkout。

官方参考：

- 官方仓库：[NVlabs/Sana](https://github.com/NVlabs/Sana)（评测器位于 `tools/metrics/sana_wm`，固定 head `6298508fcb511762a11c42cff45b2fc9fd930325`）
- 论文：[arXiv:2605.15178](https://arxiv.org/abs/2605.15178)
- 文档：[nvlabs.github.io/Sana/docs/sana-wm-bench](https://nvlabs.github.io/Sana/docs/sana-wm-bench/)
- 数据集：[Efficient-Large-Model/SANA-WM-Bench](https://huggingface.co/datasets/Efficient-Large-Model/SANA-WM-Bench)（公开、无 gating）

## 树内路径

- runner 入口：`worldfoundry/evaluation/tasks/execution/runners/sana_wm_bench/run_sana_wm_bench_official_runner.py`
- 评测实现：`worldfoundry/evaluation/tasks/execution/runners/sana_wm_bench/sana_wm_bench_official_impl.py`
- 生成请求物化：`worldfoundry/evaluation/tasks/execution/runners/sana_wm_bench/sana_wm_bench_prompts.py`
- catalog 条目：`worldfoundry/data/benchmarks/catalog/video/sana-wm-bench.yaml`
- task YAML：`worldfoundry/data/benchmarks/tasks/external/sana-wm-bench.yaml`
- runtime profile：`worldfoundry/data/benchmarks/runtime_profiles/official/sana-wm-bench.yaml`

仓库中没有 `worldfoundry/data/benchmarks/assets/sana-wm-bench` 目录；全部基准数据来自公开的 Hugging Face 数据集。

VBench 各维度由共享的树内 VBench runtime 计算，路径为 `worldfoundry/evaluation/tasks/execution/runners/vbench/runtime/vbench`，官方维度权重与归一化边界从 `vbench_official_impl.py` 导入。这是对共享 scorer 的复用，不是另一套 VBench 实现。LPIPS 使用标准 `lpips` 包（AlexNet 骨干）；重访 SSIM 需要 `scipy`。

## 评测协议与数据布局

下载公开数据集：

```bash
hf download Efficient-Large-Model/SANA-WM-Bench \
  --repo-type dataset \
  --local-dir /path/to/datasets/SANA-WM-Bench
```

两个逻辑划分对应以下数据集目录：

| 划分 | 数据集目录 |
| --- | --- |
| `simple_60s` | `benchmark_v2_smooth_60s/` |
| `hard_60s` | `benchmark_v2_hard_60s/` |

每个划分的预期数据集布局：

```text
/path/to/datasets/SANA-WM-Bench/
  images/<scene_id>.png                                  # 80 张固定首帧（两个划分共享）
  benchmark_v2_smooth_60s/
    sanawm_export_v2/run_manifest.jsonl                  # 80 行场景清单：id、prompt、image_path、camera_path
    sanawm_export_v2/<scene_id>.npz                      # c2w 相机轨迹 + 内嵌内参
    scene_trajectories_v2.json                           # 重访 evaluation_pairs 元数据
  benchmark_v2_hard_60s/
    ... 结构相同 ...
```

每行 manifest 将场景 id 绑定到一条 prompt、一张首帧图和一条相机轨迹。规范规模为每划分 80 个场景、每场景 961 帧、16 FPS。未设置 `--limit` 时 runner 采用严格模式：若某划分不是恰好 80 个场景，或任一场景资产缺失，将直接失败。

生成视频必须命名为 `<scene_id>_generated.mp4`。runner 既接受扁平目录，也接受按划分分子目录的布局：

```text
results/my_method/
  simple_60s/
    <scene_id>_generated.mp4
    ...
  hard_60s/
    <scene_id>_generated.mp4
    ...
```

不以 `_generated.mp4` 结尾的文件会被忽略。每个划分的覆盖率（预期视频数 vs 实际找到数）会记录进 scorecard。

## 指标

Scorecard 的 leaderboard 主键为 `<split>.<metric_id>`，例如 `simple_60s.vbench_overall`。没有跨划分的单一聚合值；两个划分需分别报告。

| 指标 id | 含义 | 方向 |
| --- | --- | --- |
| `vbench_overall` | 7 个 VBench 质量维度的加权得分，缩放到 0-100。每划分主键。 | 越高越好 |
| `vbench_total_score` | 诊断性指标：全部 9 个 VBench 维度按 4:1 质量/语义混合。 | 越高越好 |
| `revisit_psnr` | 来自 `scene_trajectories_v2.json` 的重访帧对 PSNR。 | 越高越好 |
| `revisit_ssim` | 重访帧对 SSIM。 | 越高越好 |
| `revisit_lpips` | 重访帧对 LPIPS（仅在 `--revisit-lpips` 时计算）。 | 越低越好 |
| `rot_err_deg` | 相机旋转误差（度），来自导入的 Pi3 位姿结果。 | 越低越好 |
| `trans_err_rel` | 相机平移相对误差，来自导入的 Pi3 位姿结果。 | 越低越好 |
| `cam_mc_rel` | 相机运动一致性相对误差，来自导入的 Pi3 位姿结果。 | 越低越好 |
| `delta_iq` | 时间维度成像质量退化：首窗口减末窗口的 VBench `imaging_quality`。 | 越低越好 |

使用的 9 个 VBench 维度为 `subject_consistency`、`background_consistency`、`temporal_flickering`、`motion_smoothness`、`dynamic_degree`、`aesthetic_quality`、`imaging_quality`、`overall_consistency`、`temporal_style`。时间退化分析会在固定长度窗口（默认 10 秒，`--window-seconds`）上重跑 `subject_consistency`、`background_consistency`、`temporal_flickering`、`imaging_quality` 四个维度。

## 数据与 checkpoint 准备

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_SANA_WM_BENCH_DATASET_ROOT=/path/to/datasets/SANA-WM-Bench
export WORLDFOUNDRY_GENERATED_ARTIFACT_DIR=/path/to/results/my_method
export WORLDFOUNDRY_BENCHMARK_OUTPUT_DIR=tmp/sana-wm-bench   # 可选的 --output-dir 默认值
```

VBench 各维度 checkpoint 由共享的树内 VBench runtime 解析；权重的准备方式见 [VBench 页面](/docs/evaluation/benchmark-hub/vbench)。重访 LPIPS 首次使用时通过 `lpips` 包下载 AlexNet LPIPS 权重。

相机位姿指标在本 runner 中是纯导入的：先把 Pi3 位姿估计作为单独的分布式 GPU 阶段跑完，再把每划分的 `eval_poses.json` 放到生成视频旁（`<generated_dir>/<split>/eval_poses.json`），或用 `--pose-results-path` 指定。每场景行的预期键为 `RotErr`（可带 `RotErr_unit: rad`）、`TransErr_rel`、`CamMC_rel`。

## 生成候选视频

`sana_wm_bench_prompts.py` 会为每行 manifest 物化一个生成请求，包含 prompt、首帧、相机轨迹（`c2w_npz`，内参内嵌）、`fps=16` 与 `num_frames=961`，并要求输出产物为 `<scene_id>_generated.mp4`。模型侧生成通过 WorldFoundry 的生成工作流执行；拷贝辅助函数会强制精确的官方文件名布局。

## 运行官方评测

通过统一基准入口运行（数据集根目录从 `WORLDFOUNDRY_SANA_WM_BENCH_DATASET_ROOT` 读取）：

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id sana-wm-bench \
  --mode official-run \
  --generated-artifact-dir "${WORLDFOUNDRY_GENERATED_ARTIFACT_DIR}" \
  --env WORLDFOUNDRY_SANA_WM_BENCH_DATASET_ROOT="${WORLDFOUNDRY_SANA_WM_BENCH_DATASET_ROOT}" \
  --output-dir tmp/sana-wm-bench/official-run \
  --json
```

需要公共包装器未透出的参数（`--split`、`--metrics`、`--limit`、`--max-pairs`、`--revisit-lpips`、`--pose-results-path`、`--device`、`--window-seconds`）时，直接调用 runner：

```bash
PYTHONPATH=. "${WORLDFOUNDRY_UNIFIED_PYTHON:-python}" \
  worldfoundry/evaluation/tasks/execution/runners/sana_wm_bench/run_sana_wm_bench_official_runner.py \
  --run-official \
  --dataset-root "${WORLDFOUNDRY_SANA_WM_BENCH_DATASET_ROOT}" \
  --generated-video-dir "${WORLDFOUNDRY_GENERATED_ARTIFACT_DIR}" \
  --split all \
  --metrics vbench,revisit,temporal,camera \
  --revisit-lpips \
  --device cuda \
  --output-dir tmp/sana-wm-bench/official-run \
  --json
```

`--split` 接受 `all`、`simple_60s` 或 `hard_60s`（别名 `simple`/`hard`）。`--metrics` 是 `vbench,revisit,temporal,camera` 的逗号分隔子集。`--limit N` 只评前 N 个场景，用于有界冒烟运行，并关闭严格的 80 场景校验。

## 导入已有结果

若已有符合 runner 记录 schema 的聚合结果 JSON（`records: [{split, vbench: {quality, total}, revisit: {psnr, ssim, lpips}, camera: {rot_err_deg, trans_err_rel, cam_mc_rel}, temporal: {imaging_quality_drop}}]`），可直接导入而不执行任何评测器：

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id sana-wm-bench \
  --mode official-validation \
  --official-results-path /path/to/aggregate_results.json \
  --generated-artifact-dir "${WORLDFOUNDRY_GENERATED_ARTIFACT_DIR}" \
  --output-dir tmp/sana-wm-bench/official-validation \
  --json
```

直接调用 runner 时用同样的 `--official-results-path` 传入该文件。`--run-fixture` 只写入确定性的占位记录，仅用于接线测试；绝不要报告 fixture 数值。

## 输出产物

运行会在 `--output-dir` 下写入：

- `scorecard.json`：WorldFoundry scorecard，含每划分指标、`<split>.<metric_id>` leaderboard 主键与每划分视频覆盖率。
- `raw_metric_table.jsonl`：每划分每指标一行，带 `higher_is_better` 与可用性标记。
- `eval/<split>/vbench/`：VBench 各维度的原始结果 JSON。
- `eval/<split>/revisit_consistency.json`：每场景重访帧对与 PSNR/SSIM/LPIPS 汇总。
- `eval/<split>/temporal_degradation.json` 与 `eval/<split>/temporal/windows/`：`delta_iq` 背后的窗口切片与 VBench 趋势数据。

## 不能声称的边界

- 本地 scorecard 不是 NVIDIA leaderboard 提交；scorecard 中硬编码 `leaderboard_valid: false`。
- 本 checkout 尚未跑过完整 80 场景 × 两划分的数值对齐（`official_benchmark_verified: false`）；目前只验证过有界 fixture 接线。
- 全新的 Pi3 相机位姿估计刻意作为单独的分布式 GPU 阶段。本 runner 只导入其 `eval_poses.json`；不提供该文件时相机指标缺失。
- `--run-fixture` 与结果导入产出的是归一化 scorecard，不是官方 runtime 证据。
- 运行 VBench、重访与时间退化指标需要 CUDA GPU 及 VBench 权重；本页不声称这些运行已在此环境执行过。
