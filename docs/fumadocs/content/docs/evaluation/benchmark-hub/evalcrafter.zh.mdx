## 简介

**发表机构：** 腾讯 AI Lab 与香港城市大学

EvalCrafter 在 700 条 prompt suite 上用约 17 个客观指标评测文生视频模型，分四个方面：视觉质量（DOVER aesthetic/technical VQA、inception score）、文本-视频对齐（CLIP score、BLIP-BLEU、SD score、detection/color/count score、OCR error、celebrity ID error）、运动质量（action score、motion AC score、flow score）与时序一致性（CLIP temporal score、warping error、face consistency）。

WorldFoundry 仓内保留 CLIP 系子集的原始指标实现（`evalcrafter_raw_metrics.py`）以及官方 EvalCrafter 结果导出的 normalizer；两条路径都转换成标准 scorecard。内置 `sample_results.txt` 支持导入冒烟运行。

官方参考：

- Paper: [arxiv.org/abs/2310.11440](https://arxiv.org/abs/2310.11440)
- 项目主页: [evalcrafter.github.io](http://evalcrafter.github.io)
- 官方仓库: [evalcrafter/EvalCrafter](https://github.com/evalcrafter/EvalCrafter)

## 评测协议

生成视频必须是与官方 prompt 列表顺序对应的编号 MP4（`0000.mp4`、`0001.mp4`……）。`--run-official` 直接从视频计算仓内指标子集；`--from-upstream-results` 或 `--official-results-path` 导入官方指标导出；`--metrics` 选择指标族，`--check-inputs` 预检目录布局。

主指标是 `evalcrafter_total`。

| Metric | 含义 | 方向 |
| --- | --- | --- |
| `visual_quality` | EvalCrafter 视觉质量得分。 | 越高越好 |
| `text_video_alignment` | EvalCrafter 文本-视频对齐得分。 | 越高越好 |
| `motion_quality` | EvalCrafter 运动质量得分。 | 越高越好 |
| `temporal_consistency` | EvalCrafter 时序一致性得分。 | 越高越好 |
| `evalcrafter_total` | EvalCrafter 聚合总分。 | 越高越好 |
| `vqa_aesthetic` | DOVER 美学组件分。 | 越高越好 |
| `vqa_technical` | DOVER 技术组件分。 | 越高越好 |
| `inception_score` | EvalCrafter IS（Inception Score）组件分。 | 越高越好 |
| `clip_temp_score` | 时序 CLIP 组件分。 | 越高越好 |
| `warping_error` | 时序 warping 误差；越低越好。 | 越低越好 |
| `face_consistency_score` | 人脸一致性组件分。 | 越高越好 |
| `action_score` | 动作识别组件分。 | 越高越好 |
| `motion_ac_score` | 运动活跃度组件分。 | 越高越好 |
| `flow_score` | 光流组件分。 | 越高越好 |
| `clip_score` | CLIP 对齐组件分。 | 越高越好 |
| `blip_bleu` | BLIP/BLEU 对齐组件分。 | 越高越好 |
| `sd_score` | Stable-diffusion 对齐组件分。 | 越高越好 |
| `detection_score` | 检测对齐组件分。 | 越高越好 |
| `color_score` | 颜色对齐组件分。 | 越高越好 |
| `count_score` | 物体数量对齐组件分。 | 越高越好 |
| `ocr_error` | OCR 不匹配组件分。 | 越低越好 |
| `celebrity_id_error` | 名人身份不匹配组件分。 | 越低越好 |

## 运行评测

目录 manifest 记录的 validation 命令：

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id evalcrafter \
  --mode official-validation \
  --official-results-path worldfoundry/data/benchmarks/assets/evalcrafter/sample_results.txt \
  --output-dir tmp/benchmark_zoo/evalcrafter-import-smoke \
  --json
```

从生成视频计算仓内指标子集：

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id evalcrafter \
  --mode official-run \
  --generated-artifact-dir "${WORLDFOUNDRY_GENERATED_ARTIFACT_DIR}" \
  --output-dir tmp/evalcrafter/official-run \
  --json
```

## 权重与环境变量

- `WORLDFOUNDRY_EVALCRAFTER_ROOT`: 可选覆盖项，指向外部 runtime checkout。
- `WORLDFOUNDRY_EVALCRAFTER_RESULTS_PATH`: 未显式传 `--official-results-path` 时，导入器默认从该路径读取官方结果导出文件。
- `WORLDFOUNDRY_GENERATED_ARTIFACT_DIR`: 存放待评测生成产物（候选视频/rollout）的目录。
- `WORLDFOUNDRY_CLIP_VIT_B32_MODEL_DIR`: 仓内指标子集使用的本地 CLIP ViT-B/32 权重目录。

共享 checkpoint 资产：`clip_vit_b32`。

该 benchmark 复用共享 base-model 依赖栈：`clip_vit_b32`。

## 输出文件

运行会在 `--output-dir` 下写出：

- `scorecard.json`: WorldFoundry 统一 scorecard，记录上表中的指标值。
- `benchmark_contract.json`: 本次运行的 benchmark contract 记录（输入、模式、来源信息）。
- `raw_metric_table.jsonl`: 支撑 scorecard 的原始 metric 行。

Scorecard 主键：`evalcrafter_total`（leaderboard key `Total`），写入 `scorecard.json`。

## 边界与限制

- 仓内 `official-run` 路径只重算 CLIP 系子集；DOVER/RAFT/人脸模型指标需要各自上游权重。
- 17 项指标的 leaderboard 对齐需要在 700 条 prompt suite 上运行完整官方指标栈。
- 本地 scorecard 不是 EvalCrafter leaderboard 提交。
