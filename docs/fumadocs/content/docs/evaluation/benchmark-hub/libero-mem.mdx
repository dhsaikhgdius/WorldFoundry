## About

LIBERO-Mem is a memory-focused extension of the LIBERO manipulation benchmark. Tasks are designed so that success depends on remembering earlier observations (object placements, scene events) across long horizons, probing whether vision-language-action policies maintain usable temporal memory rather than reacting to the current frame only.

WorldFoundry integrates LIBERO-Mem with an in-tree closed-loop simulator adapter at `worldfoundry/evaluation/tasks/embodied/simulators/libero_mem/` plus the shared official result normalizer for caller-provided rollout dumps. The catalog verification status is `normalizer_only`: result import is verified, while full official rollouts require the LIBERO runtime, LIBERO-Mem task assets, and a policy checkpoint.

Official references:

- Paper: [arXiv:2310.07899](https://arxiv.org/abs/2310.07899) (catalog `paper_url`)
- Official source reference: [Lifelong-Robot-Learning/LIBERO](https://github.com/Lifelong-Robot-Learning/LIBERO)
- License: MIT

## In-tree integration

- Catalog: `worldfoundry/data/benchmarks/catalog/embodied/libero-mem.yaml`
- Task manifest: `worldfoundry/data/benchmarks/tasks/external/libero-mem.yaml`
- Runtime profile: `worldfoundry/data/benchmarks/runtime_profiles/official/libero-mem.yaml`
- Simulator adapter: `worldfoundry/evaluation/tasks/embodied/simulators/libero_mem/`
- Closed-loop eval config: `worldfoundry/data/benchmarks/eval_configs/embodied/libero-mem/eval.yaml`
- Result normalizer: `worldfoundry.evaluation.tasks.embodied.normalizer` (track `vla`)

## Evaluation protocol and result layout

For result import, the embodied normalizer accepts JSON, JSONL, CSV, TSV, and `result.txt`-style logs. Rows are matched on numeric fields such as `success`, `success_rate`, `task_success`, and `action_accuracy`; booleans and percent strings are coerced to unit-interval floats, and episode identity is read from `sample_id`/`episode_id`/`task_id`/`task`/`id`/`name`.

The bundled eval config runs suite `libero_mem` with seed 7, 10 warm-up steps, 50 episodes per task over up to 10 tasks, against an external policy server at `ws://localhost:8000`.

## Metrics

Primary metric (scorecard key): `success_rate`.

| Metric | Meaning |
| --- | --- |
| `success_rate` | Share of rollouts completed successfully; primary leaderboard value. |
| `memory_success_rate` | Success restricted to memory-dependent task splits, when reported. |
| `task_success` | Per-task success aggregated across episodes. |
| `action_accuracy` | Agreement of predicted actions with reference actions where reported. |

Success metrics are normalized via the shared registry (`percent_or_fraction_to_unit`). No video-generation metrics apply.

## Preparation and environment

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_LIBERO_MEM_ROOT=/path/to/LIBERO
export WORLDFOUNDRY_LIBERO_MEM_RESULTS_PATH=/path/to/libero_mem_results.json
```

Closed-loop rollouts require the LIBERO runtime, LIBERO-Mem task assets, and a policy checkpoint served over WebSocket (catalog `required_assets`).

Verify runtime wiring without launching the simulator:

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile libero-mem \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/libero-mem.yaml \
  --output-dir tmp/worldfoundry_preflight/libero-mem \
  --json
```

## Import official results (official-validation)

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id libero-mem \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_LIBERO_MEM_RESULTS_PATH}" \
  --output-dir tmp/libero-mem/official-validation \
  --json
```

This routes through the embodied `vla`-track normalizer in-process; no simulator code is executed.

## Closed-loop rollouts (native simulator)

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/libero-mem/eval.yaml \
  --output-dir tmp/libero-mem/embodied-run \
  --json
```

`--server-url`, `--shard-id`/`--num-shards`, and `--no-docker` are supported by the `embodied run` entry point.

## Outputs

- `scorecard.json`: WorldFoundry scorecard; leaderboard block keyed by `success_rate`.
- `raw_results.jsonl`: extracted raw result rows.
- `evaluation/summary.json`: aggregated per-metric statistics.
- `evaluation/per_sample_metrics.jsonl`: normalized per-episode rows.

## What this page does not claim

- Catalog status is `normalizer_only` with `leaderboard_valid: false` and `official_benchmark_verified: false`. Imported numbers are normalized copies of caller-provided results, not officially reproduced leaderboard values.
- LIBERO-Mem task assets, simulator runtime, and policy checkpoints are not bundled; closed-loop rollouts require an external LIBERO installation and a policy server. No local GPU rollout evidence is claimed.
- Full leaderboard parity is not claimed until official rollouts are executed and imported (catalog blocker).
