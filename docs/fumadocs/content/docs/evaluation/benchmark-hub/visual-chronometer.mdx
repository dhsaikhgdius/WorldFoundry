## About

**Publisher:** TACO Group, Texas A&M University

Visual Chronometer predicts the Physical Frames Per Second (PhyFPS) of a video — the true temporal scale implied by its visual dynamics — bypassing unreliable container metadata. Trained via controlled temporal resampling with physics-grounded augmentations (motion blur, rolling shutter), it exposes temporal instability in both real and generated footage. As a WorldFoundry benchmark it scores a directory of videos with mean PhyFPS plus intra-/inter-video coefficients of variation; lower values indicate steadier, more consistent temporal behavior.

WorldFoundry runs PhyFPS prediction in-process through the checked-in runtime wrapper shared with PhyFPS-Bench-Gen.

Official references:

- Official repository: [taco-group/Visual_Chronometer](https://github.com/taco-group/Visual_Chronometer)

## Evaluation protocol

Point `--generated-artifact-dir` at any directory of videos; the runner slides windows over each clip, predicts per-window PhyFPS, and aggregates. `WORLDFOUNDRY_VISUAL_CHRONOMETER_PREDICT_BACKEND` selects the local prediction backend. `official-validation` mode normalizes an existing `results.csv` instead of re-predicting.

Primary metric: `visual_chronometer_average`.

| Metric | Meaning | Direction |
| --- | --- | --- |
| `mean_phyfps` | Mean average PhyFPS across evaluated videos. | Lower is better |
| `inter_video_cv` | Cross-video coefficient of variation over average PhyFPS. | Lower is better |
| `intra_video_cv` | Mean within-video coefficient of variation over sliding-window clips. | Lower is better |
| `visual_chronometer_average` | Mean over available Visual Chronometer consistency score families. | Lower is better |

```text
<out>/results.csv                                          # per-clip PhyFPS predictions
```

The VC-Common checkpoint (`xiangbog/Visual_Chronometer`, 10-60 FPS range) is required for real predictions.

## Run the benchmark

Catalog-recorded validation command:

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id visual-chronometer \
  --mode official-validation \
  --official-results-path <results.csv> \
  --generated-artifact-dir <generated_videos> \
  --output-dir <out> \
  --json
```

## Checkpoints and environment variables

- `WORLDFOUNDRY_VISUAL_CHRONOMETER_ROOT`: Optional override pointing at an external runtime checkout.
- `WORLDFOUNDRY_VISUAL_CHRONOMETER_RESULTS_PATH`: Default path the importer reads official result exports from when `--official-results-path` is not passed.
- `WORLDFOUNDRY_GENERATED_ARTIFACT_DIR`: Directory containing the candidate generated artifacts to score or import against.
- `WORLDFOUNDRY_VISUAL_CHRONOMETER_PREDICT_BACKEND`: Selects the local PhyFPS prediction backend.

## Outputs

The run writes into `--output-dir`:

- `scorecard.json`: WorldFoundry scorecard with the metric values recorded above.
- `benchmark_contract.json`: Benchmark contract record for the run (inputs, mode, provenance).
- `raw_metric_table.jsonl`: Metric rows backing the scorecard.
- `results.csv`
- `per_sample_scores.jsonl`: Per-sample rows when the result source exposes sample-level values.

Scorecard primary key: `visual_chronometer_average` (leaderboard key `visual_chronometer_average`), stored in `scorecard.json`.

## Limitations

- Full leaderboard parity requires the complete official checkpoint assets and verified scorecard evidence.
- The released VC-Common checkpoint covers 10-60 FPS and is not the authors' strongest internal model.
- Mock prediction backends are wiring-only and never benchmark evidence.
