## About

Kinetix is an open-ended space of 2D rigid-body physics control tasks implemented in JAX. It procedurally expresses environments from classic control (cartpole, lunar lander, walkers) to grasping and dexterous manipulation in a unified simulator, and is used to study large-scale online RL and generalist agents trained across task distributions.

WorldFoundry integrates Kinetix with an in-tree closed-loop simulator adapter at `worldfoundry/evaluation/tasks/embodied/simulators/kinetix/` plus the shared official result normalizer for caller-provided rollout dumps. The catalog verification status is `normalizer_only`: result import is verified, while full official rollouts require the Kinetix checkout, a JAX simulator runtime, and a policy checkpoint.

Official references:

- Paper: [arXiv:2410.23208](https://arxiv.org/abs/2410.23208)
- Official source reference: [FLAIROx/Kinetix](https://github.com/FLAIROx/Kinetix)

## In-tree integration

- Catalog: `worldfoundry/data/benchmarks/catalog/embodied/kinetix.yaml`
- Task manifest: `worldfoundry/data/benchmarks/tasks/external/kinetix.yaml`
- Runtime profile: `worldfoundry/data/benchmarks/runtime_profiles/official/kinetix.yaml`
- Simulator adapter: `worldfoundry/evaluation/tasks/embodied/simulators/kinetix/`
- Closed-loop eval config: `worldfoundry/data/benchmarks/eval_configs/embodied/kinetix/eval.yaml`
- Result normalizer: `worldfoundry.evaluation.tasks.embodied.normalizer` (track `vla`)

## Evaluation protocol and result layout

For result import, the embodied normalizer accepts JSON, JSONL, CSV, TSV, and `result.txt`-style logs. Rows are matched on numeric fields such as `success`, `success_rate`, `task_success`, `episode_success`, and `reward`; booleans and percent strings are coerced to unit-interval floats.

The bundled eval config rolls out 12 named tasks (`Grasp Easy`, `Catapult`, `Cartpole Thrust`, `Hard Lunar Lander`, `Half Cheetah`, `Swimmer`, `Walker`, `Unicycle`, `Chain Lander`, `Catcher`, `Trampoline`, `Car Launch`) with symbolic observations, 256 max episode steps, action noise 0.1, seed 0, and 100 episodes per task, against an external policy server at `ws://localhost:8000`. World definitions are read from an `rtc_worlds_dir` (default `/app/rtc/worlds` in the config).

## Metrics

Primary metric (scorecard key): `success_rate`.

| Metric | Meaning |
| --- | --- |
| `success_rate` | Share of episodes solved; primary leaderboard value. |
| `task_success` | Per-task success aggregated across episodes. |
| `episode_success` | Per-episode binary success. |
| `reward` | Cumulative episode reward. |

Success metrics are normalized via the shared registry (`percent_or_fraction_to_unit`). No video-generation metrics apply.

## Preparation and environment

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_KINETIX_ROOT=/path/to/Kinetix
export WORLDFOUNDRY_KINETIX_RESULTS_PATH=/path/to/kinetix_results.json
```

The runtime profile flags `needs_new_env: true`: keep Kinetix in a JAX-compatible simulator environment when the unified PyTorch runtime is insufficient. Closed-loop rollouts additionally require the Kinetix world assets and a policy checkpoint served over WebSocket.

Verify runtime wiring:

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile kinetix \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/kinetix.yaml \
  --output-dir tmp/worldfoundry_preflight/kinetix \
  --json
```

## Import official results (official-validation)

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id kinetix \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_KINETIX_RESULTS_PATH}" \
  --output-dir tmp/kinetix/official-validation \
  --json
```

This routes through the embodied `vla`-track normalizer in-process; no simulator code is executed.

## Closed-loop rollouts (native simulator)

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/kinetix/eval.yaml \
  --output-dir tmp/kinetix/embodied-run \
  --json
```

`--server-url`, `--shard-id`/`--num-shards`, and `--no-docker` are supported by the `embodied run` entry point.

## Outputs

- `scorecard.json`: WorldFoundry scorecard; leaderboard block keyed by `success_rate`.
- `raw_results.jsonl`: extracted raw result rows.
- `evaluation/summary.json`: aggregated per-metric statistics.
- `evaluation/per_sample_metrics.jsonl`: normalized per-episode rows.

## What this page does not claim

- Catalog status is `normalizer_only` with `leaderboard_valid: false` and `official_benchmark_verified: false`. Imported numbers are normalized copies of caller-provided results, not officially reproduced leaderboard values.
- The JAX simulator runtime, Kinetix world assets, and policy checkpoints are not bundled; closed-loop rollouts require a separate JAX-compatible environment and a policy server. No local GPU rollout evidence is claimed.
- Full leaderboard parity is not claimed until official rollouts are executed and imported (catalog blocker).
