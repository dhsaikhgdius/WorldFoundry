## 关于

Kinetix 是用 JAX 实现的开放式二维刚体物理控制任务空间。它在统一仿真器中程序化表达从经典控制（cartpole、lunar lander、walker）到抓取与灵巧操作的环境，用于研究大规模在线强化学习与跨任务分布训练的通用智能体。

WorldFoundry 通过仓内闭环仿真适配器 `worldfoundry/evaluation/tasks/embodied/simulators/kinetix/` 以及共享官方结果归一化器集成 Kinetix。catalog 校验状态为 `normalizer_only`：结果导入已验证，完整官方 rollout 需要 Kinetix checkout、JAX 仿真运行时与策略 checkpoint。

官方来源：

- 论文：[arXiv:2410.23208](https://arxiv.org/abs/2410.23208)
- 官方仓库：[FLAIROx/Kinetix](https://github.com/FLAIROx/Kinetix)
- 许可：上游条款（见仓库）

## 仓内路径

- Catalog：`worldfoundry/data/benchmarks/catalog/embodied/kinetix.yaml`
- 任务清单：`worldfoundry/data/benchmarks/tasks/external/kinetix.yaml`
- 运行时 profile：`worldfoundry/data/benchmarks/runtime_profiles/official/kinetix.yaml`
- 仿真适配器：`worldfoundry/evaluation/tasks/embodied/simulators/kinetix/`
- 闭环 eval config：`worldfoundry/data/benchmarks/eval_configs/embodied/kinetix/eval.yaml`
- 结果归一化器：`worldfoundry.evaluation.tasks.embodied.normalizer`（track `vla`）

## 评测协议与数据布局

结果导入侧，embodied normalizer 接受 JSON、JSONL、CSV、TSV 及 `result.txt` 风格日志。行记录按 `success`、`success_rate`、`task_success`、`episode_success`、`reward` 等数值字段匹配；布尔值与百分比字符串会被强制转换为 [0,1] 浮点数。

内置 eval config rollout 12 个命名任务（`Grasp Easy`、`Catapult`、`Cartpole Thrust`、`Hard Lunar Lander`、`Half Cheetah`、`Swimmer`、`Walker`、`Unicycle`、`Chain Lander`、`Catcher`、`Trampoline`、`Car Launch`），符号观测、单 episode 最长 256 步、动作噪声 0.1、seed 0、每任务 100 个 episode，由 `ws://localhost:8000` 上的外部 policy server 驱动。世界定义从 `rtc_worlds_dir` 读取（config 中默认 `/app/rtc/worlds`）。

## 指标

主指标（scorecard 主键）：`success_rate`。

| 指标 | 含义 |
| --- | --- |
| `success_rate` | 解决的 episode 占比；leaderboard 主值。 |
| `task_success` | 按任务聚合的成功率。 |
| `episode_success` | 单 episode 的二值成功。 |
| `reward` | episode 累计奖励。 |

成功类指标经共享 registry 的 `percent_or_fraction_to_unit` 归一化；不涉及视频生成类指标。

## 准备命令与环境变量

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_KINETIX_ROOT=/path/to/Kinetix
export WORLDFOUNDRY_KINETIX_RESULTS_PATH=/path/to/kinetix_results.json
```

运行时 profile 标记 `needs_new_env: true`：统一 PyTorch 运行时不满足需求时，应把 Kinetix 放在兼容 JAX 的独立仿真环境中。闭环 rollout 还需要 Kinetix world assets 与通过 WebSocket 提供动作的策略 checkpoint。

校验运行时接线：

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile kinetix \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/kinetix.yaml \
  --output-dir tmp/worldfoundry_preflight/kinetix \
  --json
```

## 导入官方结果（official-validation）

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id kinetix \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_KINETIX_RESULTS_PATH}" \
  --output-dir tmp/kinetix/official-validation \
  --json
```

该路径在进程内走 embodied `vla` track normalizer，不执行任何仿真代码。

## 闭环 rollout（原生仿真器）

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/kinetix/eval.yaml \
  --output-dir tmp/kinetix/embodied-run \
  --json
```

`embodied run` 入口支持 `--server-url`、`--shard-id`/`--num-shards`、`--no-docker`。

## 输出

- `scorecard.json`：WorldFoundry scorecard；leaderboard 块以 `success_rate` 为主键。
- `raw_results.jsonl`：提取的原始结果行。
- `evaluation/summary.json`：按指标聚合的统计。
- `evaluation/per_sample_metrics.jsonl`：归一化后的逐 episode 行。

## 不能声称的边界

- catalog 状态为 `normalizer_only`，`leaderboard_valid: false`、`official_benchmark_verified: false`。导入的数字是调用方结果的归一化副本，不是官方复现的 leaderboard 值。
- JAX 仿真运行时、Kinetix world assets、策略 checkpoint 均未随仓库分发；闭环 rollout 需要独立的 JAX 兼容环境并运行 policy server。本页不声称任何本地 GPU rollout 证据。
- catalog blocker：官方 rollout 执行并导入之前，不声称完整 leaderboard 对齐。
