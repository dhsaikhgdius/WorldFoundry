## About

**Publisher:** Stanford University

WorldScore unifies the evaluation of world generation — 3D/4D scene generation and video-based world models — into one protocol: a model receives a starting scene and a sequence of camera-specified layout instructions, and its rollouts are scored on controllability (camera and object control), quality (visual and reconstruction fidelity), and dynamics (temporal behavior). The official aggregate `worldscore_average` normalizes these families onto one scale.

WorldFoundry vendors the WorldScore core runtime in tree and drives it through `run_worldscore_official_runner.py`, which resolves the dataset (`Howieeeee/WorldScore` on Hugging Face), stages generated output trees, dispatches the upstream metric stack, and converts `evaluation.json` trees into scorecards.

Official references:

- Paper: [arxiv.org/abs/2504.00983](https://arxiv.org/abs/2504.00983)
- Project page: [haoyi-duan.github.io/WorldScore](https://haoyi-duan.github.io/WorldScore/)
- Official repository: [haoyi-duan/WorldScore](https://github.com/haoyi-duan/WorldScore)
- License: `mit`

## Evaluation protocol

Two paths: normalize existing WorldScore result artifacts via `--official-results-path` / `WORLDFOUNDRY_WORLDSCORE_RESULTS_PATH`, or evaluate a staged generated-output tree with the vendored GPU metric runtime (`--generated-root`, `--data-path`, `--num-jobs`). Dataset resolution falls back to a local Hugging Face cache snapshot when `--data-path` is not given. Staging helpers (`--stage-dynamic-source`, `--stage-sample-index`, `--stage-target-frames`) prepare dynamic samples.

Primary metric: `worldscore_average`.

| Metric | Meaning | Direction |
| --- | --- | --- |
| `controllability` | WorldScore camera and condition controllability metric family. | Higher is better |
| `quality` | WorldScore visual and reconstruction quality metric family. | Higher is better |
| `dynamics` | WorldScore temporal dynamics metric family. | Higher is better |
| `worldscore_average` | Normalized aggregate across WorldScore metric families. | Higher is better |

## Run the benchmark

Catalog-recorded validation command:

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id worldscore \
  --mode official-validation \
  --official-results-path <official_results.json> \
  --generated-artifact-dir <generated_videos> \
  --output-dir <out> \
  --json
```

## Checkpoints and environment variables

- `WORLDFOUNDRY_WORLDSCORE_ROOT`: Optional override pointing at a local benchmark runtime/repository root.
- `WORLDFOUNDRY_GENERATED_ARTIFACT_DIR`: Directory containing the candidate generated artifacts to score or import against.
- `WORLDFOUNDRY_WORLDSCORE_RESULTS_PATH`
- `WORLDFOUNDRY_WORLDSCORE_OUTPUT_DIR`
- `WORLDFOUNDRY_WORLDSCORE_CONFIG_ROOT`: Optional override for bundled WorldScore config assets.

This benchmark reuses the shared base-model dependency stack: `worldscore_spatial_metric_stack`.

## Outputs

The run writes into `--output-dir`:

- `scorecard.json`: WorldFoundry scorecard with the metric values recorded above.
- `per_sample_metrics.jsonl`
- `raw_metric_table.jsonl`: Metric rows backing the scorecard.
- `official_stdout.log`
- `official_stderr.log`

Scorecard primary key: `worldscore_average` (leaderboard key `worldscore_average`), stored in `scorecard.json`.

## Limitations

- Bounded official GPU validation covered one dynamic sample; full-suite validation is pending, so `official_benchmark_verified` remains false.
- Leaderboard parity requires complete `evaluation.json` trees under the official metric definitions; partial trees aggregate into non-leaderboard scorecards.
- The spatial metric stack (DROID, GroundingDINO, SAM, RAFT/SEA-RAFT) needs its shared checkpoints staged locally.
