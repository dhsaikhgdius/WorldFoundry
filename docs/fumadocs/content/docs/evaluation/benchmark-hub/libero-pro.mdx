## About

LIBERO-Pro extends the LIBERO manipulation benchmark with procedurally varied task instances — for example swapping target objects (the bundled config runs `libero_spatial_with_mug`) — to test whether vision-language-action policies generalize beyond the exact object sets seen during training.

WorldFoundry integrates LIBERO-Pro with an in-tree closed-loop simulator adapter at `worldfoundry/evaluation/tasks/embodied/simulators/libero_pro/` plus the shared official result normalizer for caller-provided rollout dumps. The catalog verification status is `normalizer_only`: result import is verified, while full official rollouts require the LIBERO-Pro runtime, task assets, and a policy checkpoint.

Official references:

- Official source reference: [Lifelong-Robot-Learning/LIBERO](https://github.com/Lifelong-Robot-Learning/LIBERO)
- License: MIT
- The catalog records no separate paper URL for LIBERO-Pro.

## In-tree integration

- Catalog: `worldfoundry/data/benchmarks/catalog/embodied/libero-pro.yaml`
- Task manifest: `worldfoundry/data/benchmarks/tasks/external/libero-pro.yaml`
- Runtime profile: `worldfoundry/data/benchmarks/runtime_profiles/official/libero-pro.yaml`
- Simulator adapter: `worldfoundry/evaluation/tasks/embodied/simulators/libero_pro/`
- Closed-loop eval config: `worldfoundry/data/benchmarks/eval_configs/embodied/libero-pro/eval.yaml`
- Result normalizer: `worldfoundry.evaluation.tasks.embodied.normalizer` (track `vla`)

## Evaluation protocol and result layout

For result import, the embodied normalizer accepts JSON, JSONL, CSV, TSV, and `result.txt`-style logs. Rows are matched on numeric fields such as `success`, `success_rate`, `task_success`, `episode_success`, and `action_accuracy`; booleans and percent strings are coerced to unit-interval floats.

The bundled eval config runs suite `libero_spatial_with_mug` with seed 7, 10 warm-up steps, 50 episodes per task over up to 10 tasks, against an external policy server at `ws://localhost:8000`.

## Metrics

Primary metric (scorecard key): `success_rate`.

| Metric | Meaning |
| --- | --- |
| `success_rate` | Share of rollouts completed successfully; primary leaderboard value. |
| `task_success` | Per-task success aggregated across episodes. |
| `episode_success` | Per-episode binary success. |
| `action_accuracy` | Agreement of predicted actions with reference actions where reported. |

Success metrics are normalized via the shared registry (`percent_or_fraction_to_unit`). No video-generation metrics apply.

## Preparation and environment

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_LIBERO_PRO_ROOT=/path/to/LIBERO-Pro
export WORLDFOUNDRY_LIBERO_PRO_RESULTS_PATH=/path/to/libero_pro_results.json
```

Closed-loop rollouts require the LIBERO-Pro runtime, task assets, and a policy checkpoint served over WebSocket (catalog `required_assets`).

Verify runtime wiring without launching the simulator:

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile libero-pro \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/libero-pro.yaml \
  --output-dir tmp/worldfoundry_preflight/libero-pro \
  --json
```

## Import official results (official-validation)

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id libero-pro \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_LIBERO_PRO_RESULTS_PATH}" \
  --output-dir tmp/libero-pro/official-validation \
  --json
```

This routes through the embodied `vla`-track normalizer in-process; no simulator code is executed.

## Closed-loop rollouts (native simulator)

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/libero-pro/eval.yaml \
  --output-dir tmp/libero-pro/embodied-run \
  --json
```

`--server-url`, `--shard-id`/`--num-shards`, and `--no-docker` are supported by the `embodied run` entry point.

## Outputs

- `scorecard.json`: WorldFoundry scorecard; leaderboard block keyed by `success_rate`.
- `raw_results.jsonl`: extracted raw result rows.
- `evaluation/summary.json`: aggregated per-metric statistics.
- `evaluation/per_sample_metrics.jsonl`: normalized per-episode rows.

## What this page does not claim

- Catalog status is `normalizer_only` with `leaderboard_valid: false` and `official_benchmark_verified: false`. Imported numbers are normalized copies of caller-provided results, not officially reproduced leaderboard values.
- LIBERO-Pro task assets, simulator runtime, and policy checkpoints are not bundled; closed-loop rollouts require an external installation and a policy server. No local GPU rollout evidence is claimed.
- Full leaderboard parity is not claimed until official rollouts are executed and imported (catalog blocker).
