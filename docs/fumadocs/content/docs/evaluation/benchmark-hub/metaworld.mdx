## About

Meta-World is a benchmark for multi-task and meta reinforcement learning built on MuJoCo. It defines 50 distinct simulated manipulation tasks with a shared Sawyer arm and standardized suites — MT1/MT10/MT50 for multi-task learning and ML1/ML10/ML45 for meta-learning generalization to held-out tasks — with success determined by task-specific goal predicates.

WorldFoundry integrates Meta-World as an official result normalizer only: caller-provided rollout result files (JSON/CSV exports of suite evaluations) are converted into WorldFoundry scorecards. There is no in-tree Meta-World simulator adapter, and the runtime profile flags that the Meta-World/MuJoCo runtime is not staged in the default checkout (`needs_new_env: true`).

- Task manifest: `worldfoundry/data/benchmarks/tasks/external/metaworld.yaml`
- Runtime profile: `worldfoundry/data/benchmarks/runtime_profiles/official/metaworld.yaml`
- Result normalizer: `worldfoundry.evaluation.tasks.embodied.normalizer` (track `vla`)
- No simulator adapter and no closed-loop eval config exist for this benchmark id.

## Evaluation protocol and result layout

The embodied normalizer accepts JSON, JSONL, CSV, TSV, and `result.txt`-style logs. Rows are matched on numeric fields such as `success`, `success_rate`, `task_success`, `reward`, and `normalized_return`; booleans and percent strings are coerced to unit-interval floats, and episode identity is read from `sample_id`/`episode_id`/`task_id`/`task`/`id`/`name`.

Producing the raw results requires the official Meta-World package or repository checkout, a MuJoCo-compatible runtime, an explicit MT/ML suite mapping, and a policy checkpoint or controller (catalog `requires`).

## Metrics

Primary metric (scorecard key): `success_rate`.

| Metric | Meaning |
| --- | --- |
| `success_rate` | Share of episodes meeting the task success predicate; primary leaderboard value. |
| `task_success` | Per-task success aggregated across episodes. |
| `reward` | Cumulative shaped reward per episode. |
| `normalized_return` | Return normalized against task-specific reference ranges, when reported. |

Success metrics are normalized via the shared registry (`percent_or_fraction_to_unit`). No video-generation metrics apply.

## Preparation and environment

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_METAWORLD_RESULTS_PATH=/path/to/metaworld_results.json
```

The runtime profile flags `needs_new_env: true`: a dedicated `mujoco`/`metaworld` environment is required before suite mapping, and the default checkout does not stage it.

Verify runtime wiring:

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile metaworld \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/metaworld.yaml \
  --output-dir tmp/worldfoundry_preflight/metaworld \
  --json
```

## Import official results (official-validation)

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id metaworld \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_METAWORLD_RESULTS_PATH}" \
  --output-dir tmp/metaworld/official-validation \
  --json
```

This routes through the embodied `vla`-track normalizer in-process; no simulator code is executed. There is no in-tree `official-run` rollout path for Meta-World — full runs must be executed with the upstream package and then imported.

## Outputs

- `scorecard.json`: WorldFoundry scorecard; leaderboard block keyed by `success_rate`.
- `raw_results.jsonl`: extracted raw result rows.
- `evaluation/summary.json`: aggregated per-metric statistics.
- `evaluation/per_sample_metrics.jsonl`: normalized per-episode rows.

## What this page does not claim

- Catalog status is `normalizer_only` with `leaderboard_valid: false` and `official_benchmark_verified: false`. Imported numbers are normalized copies of caller-provided results, not officially reproduced leaderboard values.
- The MuJoCo simulator and Meta-World package are not installed in the default WorldFoundry environment; running the benchmark requires an external environment. No local rollout evidence is claimed.
- Meta-World task-suite mapping and official-style policy result validation must be completed before integrated status (catalog blocker).
