## 简介

**发表机构：** Tsinghua University（清华大学，联合 NTU、Waterloo）

WorldReasonBench 把视频生成评测重构为世界状态预测：给定初始状态与一个动作，模型能否生成状态演化在物理、社会、逻辑与信息层面都保持一致的未来视频？它包含 436 个精心策划的用例，带结构化 QA 标注，覆盖四个推理维度、22 个子类。评测分两部分：过程感知推理验证（结构化 QA 加推理阶段诊断，捕捉时序与因果失败）与多维质量评估（推理质量、时序一致性、视觉美学）。配套的 WorldRewardBench 增加约 6K 专家偏好对，支持点式/对式 reward model 评测。

WorldFoundry 在仓内托管协议 runtime，judge 资产在外部：由 OpenAI 兼容的多模态 judge 为 QA 与质量维度打分。

## 评测协议

用 `--protocol` 选择协议，提供 QA/偏好对文件（`--qa-json`、`--pairs-json`）与 judge 访问参数（`--base-url`、`--api-key`、`--model`、`--judge-model`）。scorecard 主键 `score_pr` 是 QA 准确率与动态推理分的几何组合；`reasoning_gap`（静态结果分减动态推理分，越低越好）用于标记结果作弊。`--official-results-path` 归一化已有官方结果目录。

主指标是 `score_pr`。

| Metric | 含义 | 方向 |
| --- | --- | --- |
| `score_pr` | QA 准确率与动态推理得分的几何组合。 | 越高越好 |
| `qa_accuracy` | 相对真值世界状态问题的结构化 QA 准确率。 | 越高越好 |
| `state_score` | 最终预测世界状态的正确性。 | 越高越好 |
| `process_score` | 状态演化过程的推理阶段诊断分。 | 越高越好 |
| `fidelity_score` | 生成演化的内容保真度。 | 越高越好 |
| `mechanism_score` | 驱动演化的因果机制正确性。 | 越高越好 |
| `static_outcome_score` | 仅凭静态（末态）证据判定的结果分。 | 越高越好 |
| `dynamic_reasoning_score` | 基于完整时序演化判定的推理分。 | 越高越好 |
| `reasoning_gap` | 静态结果分减去动态推理分；数值越低说明结果作弊越少。 | 越低越好 |
| `pointwise_score` | 用于 reward model 评测的点式质量分。 | 越高越好 |
| `reasoning_correctness` | 多维质量评估：推理质量。 | 越高越好 |
| `content_fidelity` | 多维质量评估：时序/内容一致性。 | 越高越好 |
| `visual_aesthetics` | 多维质量评估：视觉美学。 | 越高越好 |
| `pointwise_spearman` | 点式分数与专家排名的 Spearman 相关系数。 | 越高越好 |
| `induced_pairwise_accuracy` | 由点式分数诱导的成对偏好准确率。 | 越高越好 |
| `pairwise_accuracy_with_ties` | 计入平局对的成对偏好准确率。 | 越高越好 |
| `pairwise_accuracy_without_ties` | 剔除平局对的成对偏好准确率。 | 越高越好 |

## 权重与环境变量

- `WORLDFOUNDRY_WORLDREASONBENCH_ROOT`: 可选覆盖项，指向本地 benchmark runtime / 仓库根目录。
- `WORLDFOUNDRY_WORLDREASONBENCH_RESULTS_PATH`: 未显式传 `--official-results-path` 时，导入器默认从该路径读取官方结果导出文件。
- `WORLDFOUNDRY_GENERATED_ARTIFACT_DIR`: 存放待评测生成产物（候选视频/rollout）的目录。

## 输出文件

运行会在 `--output-dir` 下写出：

- `scorecard.json`: WorldFoundry 统一 scorecard，记录上表中的指标值。
- `raw_metric_table.jsonl`: 支撑 scorecard 的原始 metric 行。
- `protocol_results.json`
- `benchmark_contract.json`: 本次运行的 benchmark contract 记录（输入、模式、来源信息）。

Scorecard 主键：`score_pr`（leaderboard key `score_pr`），写入 `scorecard.json`。

## 边界与限制
