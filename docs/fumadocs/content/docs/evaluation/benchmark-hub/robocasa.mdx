## About

RoboCasa is a large-scale simulation benchmark for training and evaluating generalist robot policies in everyday kitchen environments. It provides generatively diverse kitchen scenes, a broad set of atomic and composite manipulation tasks (pick-and-place, door/drawer articulation, appliance operation), and standardized policy rollout evaluation on top of robosuite/MuJoCo.

WorldFoundry integrates RoboCasa on two surfaces: an in-tree closed-loop simulator adapter at `worldfoundry/evaluation/tasks/embodied/simulators/robocasa/` driven by `worldfoundry-eval embodied run`, and an official result normalizer that converts caller-provided rollout result files into WorldFoundry scorecards. The catalog verification status is `normalizer_only`: result import is verified, while full official rollouts still require RoboCasa assets and a policy checkpoint.

- Closed-loop eval config: `worldfoundry/data/benchmarks/eval_configs/embodied/robocasa/eval.yaml`
- Result normalizer: `worldfoundry.evaluation.tasks.embodied.normalizer` (track `vla`)

## Evaluation protocol and result layout

For result import, the embodied normalizer accepts JSON, JSONL, CSV, TSV, and `result.txt`-style log files. Rows are matched on numeric fields such as `success`, `success_rate`, `task_success`, `episode_success`, and `reward`; booleans and `xx%` strings are coerced to unit-interval floats. Episode/task identity is read from `sample_id`, `episode_id`, `task_id`, `task`, `id`, or `name` when present.

The bundled closed-loop eval config rolls out six kitchen tasks (`PickPlaceCounterToCabinet`, `PickPlaceCounterToSink`, `OpenSingleDoor`, `CloseDoubleDoor`, `TurnOnSinkFaucet`, `PreheatOven`) with the `PandaOmron` robot, 256px cameras, 500 max steps, `pretrain` split, and 5 episodes per task, and expects an external policy server at `ws://localhost:8000`.

## Metrics

Primary metric (scorecard key): `success_rate`.

| Metric | Meaning |
| --- | --- |
| `success_rate` | Share of episodes/tasks completed successfully; primary leaderboard value. |
| `task_success` | Per-task success indicator aggregated across episodes. |
| `episode_success` | Per-episode binary success. |
| `reward` | Cumulative reward on RoboCasa kitchen manipulation tasks. |

Metric normalization uses the shared registry normalizer `percent_or_fraction_to_unit` for the success metrics; no video-generation metrics (FID/CLIP/FVD) apply to this benchmark.

## Preparation and environment

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_ROBOCASA_RESULTS_PATH=/path/to/robocasa/rollout_results.json
```

For closed-loop rollouts you additionally need the official RoboCasa repository checkout (cached at `${WORLDFOUNDRY_CACHE_DIR}/repos/robocasa--robocasa`), RoboCasa simulator assets, and a policy checkpoint served over WebSocket. The runtime profile targets a headless robosuite venv (`needs_new_env: false` relative to the unified env, with RoboCasa/robosuite importable in the headless venv).

Verify runtime wiring without launching the simulator:

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile robocasa \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/robocasa.yaml \
  --output-dir tmp/worldfoundry_preflight/robocasa \
  --json
```

## Import official results (official-validation)

Normalize an existing official-format rollout result file into a WorldFoundry scorecard:

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id robocasa \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_ROBOCASA_RESULTS_PATH}" \
  --output-dir tmp/robocasa/official-validation \
  --json
```

This routes through the embodied `vla`-track normalizer in-process; no simulator code is executed.

## Closed-loop rollouts (native simulator)

With RoboCasa installed and a policy server running, execute the bundled eval config:

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/robocasa/eval.yaml \
  --output-dir tmp/robocasa/embodied-run \
  --json
```

`--server-url`, `--shard-id`/`--num-shards`, and `--no-docker` are supported by the `embodied run` entry point. The policy must answer action requests over the WebSocket protocol used by `external-policy-server`.

## Outputs

- `scorecard.json`: WorldFoundry scorecard; leaderboard block keyed by `success_rate`.
- `raw_results.jsonl`: extracted raw result rows for auditing.
- `evaluation/summary.json`: aggregated per-metric statistics.
- `evaluation/per_sample_metrics.jsonl`: normalized per-episode/task rows.

## What this page does not claim

- Catalog status is `normalizer_only` with `leaderboard_valid: false` and `official_benchmark_verified: false`. Imported numbers are normalized copies of caller-provided results, not officially reproduced leaderboard values.
- The RoboCasa simulator, scene assets, and policy checkpoints are not bundled; closed-loop rollouts require an external RoboCasa installation and a policy server. No local GPU rollout evidence is claimed here.
- Official RoboCasa scene assets, policy checkpoints, and long-horizon simulator rollouts must be validated before integrated status (catalog blocker).
