## About

CALVIN (Composing Actions from Language and Vision) evaluates long-horizon, language-conditioned robot manipulation. Policies must chain multiple sub-tasks specified in natural language within a tabletop PyBullet environment; the canonical protocol rolls 1000 instruction sequences and reports how many consecutive sub-tasks a policy completes per sequence.

WorldFoundry integrates CALVIN with an in-tree closed-loop simulator adapter at `worldfoundry/evaluation/tasks/embodied/simulators/calvin/` plus the shared official result normalizer for caller-provided evaluation dumps. The catalog verification status is `normalizer_only`: result import is verified, while official rollouts require the CALVIN dataset, sequence evaluator, and a policy checkpoint.

## Evaluation protocol and result layout

For result import, the embodied normalizer accepts JSON, JSONL, CSV, TSV, and `result.txt`-style logs. Rows are matched on numeric fields such as `success`, `success_rate`, `task_success`, `sequence_success`, and `completion`; booleans and percent strings are coerced to unit-interval floats.

The bundled eval config evaluates 1000 instruction sequences (seed 0, one episode per sequence) against a validation dataset at `/data/calvin/dataset/validation`, driven by an external policy server at `ws://localhost:8000`.

## Metrics

Primary metric (scorecard key): `success_rate`.

| Metric | Meaning |
| --- | --- |
| `success_rate` | Share of evaluation rollouts completed successfully; primary leaderboard value. |
| `sequence_success` | Success over full multi-step instruction sequences. |
| `task_success` | Per-sub-task success aggregated across sequences. |
| `completion` | Average number/fraction of consecutive sub-tasks completed per sequence. |

Success metrics are normalized via the shared registry (`percent_or_fraction_to_unit`). No video-generation metrics apply.

## Preparation and environment

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_CALVIN_RESULTS_PATH=/path/to/calvin_results.json
```

Closed-loop rollouts require the official CALVIN repository checkout (cached at `cache/vla_va_wam/repos/mees--calvin`), a CALVIN dataset root, and a policy checkpoint served over WebSocket. The runtime profile is a lightweight preflight only (`needs_new_env: false`) and does not start the simulator or download the dataset.

Verify runtime wiring:

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile calvin \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/calvin.yaml \
  --output-dir tmp/worldfoundry_preflight/calvin \
  --json
```

## Import official results (official-validation)

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id calvin \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_CALVIN_RESULTS_PATH}" \
  --output-dir tmp/calvin/official-validation \
  --json
```

This routes through the embodied `vla`-track normalizer in-process; no simulator code is executed.

## Closed-loop rollouts (native simulator)

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/calvin/eval.yaml \
  --output-dir tmp/calvin/embodied-run \
  --json
```

Adjust `dataset_path` inside the config (or copy it) to point at your CALVIN validation split. `--server-url`, `--shard-id`/`--num-shards`, and `--no-docker` are supported.

## Outputs

- `scorecard.json`: WorldFoundry scorecard; leaderboard block keyed by `success_rate`.
- `raw_results.jsonl`: extracted raw result rows.
- `evaluation/summary.json`: aggregated per-metric statistics.
- `evaluation/per_sample_metrics.jsonl`: normalized per-sequence rows.

## What this page does not claim

- Catalog status is `normalizer_only` with `leaderboard_valid: false` and `official_benchmark_verified: false`. Imported numbers are normalized copies of caller-provided results, not officially reproduced leaderboard values.
- The CALVIN dataset, PyBullet simulator assets, and policy checkpoints are not bundled; closed-loop rollouts require external staging plus a policy server. No local GPU rollout evidence is claimed.
- Official CALVIN dataset split, sequence evaluator, and policy checkpoint validation must be completed before integrated status (catalog blocker).
