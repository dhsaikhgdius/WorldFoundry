## About

RoboCerebra evaluates deliberate, "System-2" capabilities of robot manipulation policies over long-horizon household tasks. Episodes are much longer than typical VLA benchmarks and include task types that stress planning, memory of past events, and recovery from dynamic disturbances, so success requires more than reactive control.

WorldFoundry integrates RoboCerebra with an in-tree closed-loop simulator adapter at `worldfoundry/evaluation/tasks/embodied/simulators/robocerebra/` plus the shared official result normalizer for caller-provided rollout dumps. The catalog verification status is `normalizer_only`.

Official references:

- Paper: [arXiv:2502.02853](https://arxiv.org/abs/2502.02853) (catalog `paper_url`)
- Official source reference: [buaa-colalab/RoboCerebra](https://github.com/buaa-colalab/RoboCerebra)
- License: upstream terms (see repository)

- Simulator adapter: `worldfoundry/evaluation/tasks/embodied/simulators/robocerebra/`
- Closed-loop eval config: `worldfoundry/data/benchmarks/eval_configs/embodied/robocerebra/eval.yaml`
- Result normalizer: `worldfoundry.evaluation.tasks.embodied.normalizer` (track `vla`)

## Evaluation protocol and result layout

For result import, the embodied normalizer accepts JSON, JSONL, CSV, TSV, and `result.txt`-style logs. Rows are matched on numeric fields such as `success`, `success_rate`, `task_success`, `episode_success`, and `reward`; booleans and percent strings are coerced to unit-interval floats.

The bundled eval config expects a staged benchmark root at `/workspace/RoboCerebra_Bench` (`robocerebra_root`), runs the `Ideal` task type with seed 7, one episode per task over up to 5 tasks, against an external policy server at `ws://localhost:8000`.

## Metrics

Primary metric (scorecard key): `success_rate`.

| Metric | Meaning |
| --- | --- |
| `success_rate` | Share of rollouts completed successfully; primary leaderboard value. |
| `task_success` | Per-task success aggregated across episodes. |
| `episode_success` | Per-episode binary success. |
| `reward` | Cumulative episode reward, when defined. |

Success metrics are normalized via the shared registry (`percent_or_fraction_to_unit`). No video-generation metrics apply.

## Preparation and environment

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_ROBOCEREBRA_ROOT=/path/to/RoboCerebra_Bench
export WORLDFOUNDRY_ROBOCEREBRA_RESULTS_PATH=/path/to/robocerebra_results.json
```

Closed-loop rollouts require the RoboCerebra runtime, task assets, and a policy checkpoint served over WebSocket (catalog `required_assets`).

Verify runtime wiring:

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile robocerebra \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/robocerebra.yaml \
  --output-dir tmp/worldfoundry_preflight/robocerebra \
  --json
```

## Import official results (official-validation)

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id robocerebra \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_ROBOCEREBRA_RESULTS_PATH}" \
  --output-dir tmp/robocerebra/official-validation \
  --json
```

This routes through the embodied `vla`-track normalizer in-process; no simulator code is executed.

## Closed-loop rollouts (native simulator)

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/robocerebra/eval.yaml \
  --output-dir tmp/robocerebra/embodied-run \
  --json
```

Adjust `robocerebra_root` in the config (or copy it) to your staged benchmark path. `--server-url`, `--shard-id`/`--num-shards`, and `--no-docker` are supported.

## Outputs

- `scorecard.json`: WorldFoundry scorecard; leaderboard block keyed by `success_rate`.
- `raw_results.jsonl`: extracted raw result rows.
- `evaluation/summary.json`: aggregated per-metric statistics.
- `evaluation/per_sample_metrics.jsonl`: normalized per-episode rows.

## What this page does not claim

- Catalog status is `normalizer_only` with `leaderboard_valid: false` and `official_benchmark_verified: false`. Imported numbers are normalized copies of caller-provided results, not officially reproduced leaderboard values.
- The RoboCerebra runtime, benchmark assets, and policy checkpoints are not bundled; closed-loop rollouts require external staging plus a policy server. No local GPU rollout evidence is claimed.
- Full leaderboard parity is not claimed until official rollouts are executed and imported (catalog blocker).
