## About

LIBERO-Plus stresses vision-language-action policies with perturbed variants of the LIBERO task suites. It expands each suite with thousands of perturbation instances (visual, layout, and instruction variations) so that a policy's headline success rate reflects robustness rather than memorization of the canonical scenes.

WorldFoundry integrates LIBERO-Plus with an in-tree closed-loop simulator adapter at `worldfoundry/evaluation/tasks/embodied/simulators/libero_plus/` plus the shared official result normalizer for caller-provided rollout dumps. The catalog verification status is `normalizer_only`: result import is verified, while full official rollouts require the LIBERO-Plus runtime, task assets, and a policy checkpoint.

Official references:

- Official source reference: [Lifelong-Robot-Learning/LIBERO](https://github.com/Lifelong-Robot-Learning/LIBERO)
- License: MIT
- The catalog records no separate paper URL for LIBERO-Plus.

## In-tree integration

- Catalog: `worldfoundry/data/benchmarks/catalog/embodied/libero-plus.yaml`
- Task manifest: `worldfoundry/data/benchmarks/tasks/external/libero-plus.yaml`
- Runtime profile: `worldfoundry/data/benchmarks/runtime_profiles/official/libero-plus.yaml`
- Simulator adapter: `worldfoundry/evaluation/tasks/embodied/simulators/libero_plus/`
- Closed-loop eval configs: `worldfoundry/data/benchmarks/eval_configs/embodied/libero-plus/{spatial,all}.yaml`
- Result normalizer: `worldfoundry.evaluation.tasks.embodied.normalizer` (track `vla`)

## Evaluation protocol and result layout

For result import, the embodied normalizer accepts JSON, JSONL, CSV, TSV, and `result.txt`-style logs. Rows are matched on numeric fields such as `success`, `success_rate`, `task_success`, `episode_success`, and `action_accuracy`; booleans and percent strings are coerced to unit-interval floats.

The bundled `all.yaml` eval config chains four perturbed suites against an external policy server at `ws://localhost:8000`, one episode per perturbation instance: `libero_spatial` (2402 tasks), `libero_object` (2518), `libero_goal` (2591), and `libero_10` (2519), each with seed 7 and 10 warm-up steps. `spatial.yaml` runs the spatial slice alone.

## Metrics

Primary metric (scorecard key): `success_rate`.

| Metric | Meaning |
| --- | --- |
| `success_rate` | Share of perturbed rollouts completed successfully; primary leaderboard value. |
| `task_success` | Per-task success aggregated across perturbation instances. |
| `episode_success` | Per-episode binary success. |
| `action_accuracy` | Agreement of predicted actions with reference actions where reported. |

Success metrics are normalized via the shared registry (`percent_or_fraction_to_unit`). No video-generation metrics apply.

## Preparation and environment

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_LIBERO_PLUS_ROOT=/path/to/LIBERO-Plus
export WORLDFOUNDRY_LIBERO_PLUS_RESULTS_PATH=/path/to/libero_plus_results.json
```

The runtime profile flags `needs_new_env: true`: LIBERO and LIBERO-Plus package constraints may conflict, so use a separate environment if the unified runtime cannot satisfy both. Closed-loop rollouts additionally require task assets and a policy checkpoint served over WebSocket.

Verify runtime wiring without launching the simulator:

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile libero-plus \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/libero-plus.yaml \
  --output-dir tmp/worldfoundry_preflight/libero-plus \
  --json
```

## Import official results (official-validation)

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id libero-plus \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_LIBERO_PLUS_RESULTS_PATH}" \
  --output-dir tmp/libero-plus/official-validation \
  --json
```

This routes through the embodied `vla`-track normalizer in-process; no simulator code is executed.

## Closed-loop rollouts (native simulator)

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/libero-plus/all.yaml \
  --output-dir tmp/libero-plus/embodied-run \
  --json
```

Use `spatial.yaml` for the spatial slice only. `--server-url`, `--shard-id`/`--num-shards`, and `--no-docker` are supported.

## Outputs

- `scorecard.json`: WorldFoundry scorecard; leaderboard block keyed by `success_rate`.
- `raw_results.jsonl`: extracted raw result rows.
- `evaluation/summary.json`: aggregated per-metric statistics.
- `evaluation/per_sample_metrics.jsonl`: normalized per-episode rows.

## What this page does not claim

- Catalog status is `normalizer_only` with `leaderboard_valid: false` and `official_benchmark_verified: false`. Imported numbers are normalized copies of caller-provided results, not officially reproduced leaderboard values.
- LIBERO-Plus task assets, simulator runtime, and policy checkpoints are not bundled; closed-loop rollouts require an external installation (possibly in a dedicated environment) and a policy server. No local GPU rollout evidence is claimed.
- Full leaderboard parity is not claimed until official rollouts are executed and imported (catalog blocker).
