## About

**Publisher:** S-Lab, Nanyang Technological University & Shanghai AI Laboratory

VBench decomposes video generation quality into 16 evaluation dimensions covering temporal quality (subject/background consistency, flicker, motion smoothness, dynamic degree), frame-wise quality (aesthetic and imaging quality), and semantics/text alignment (object class, multiple objects, human action, color, spatial relationship, scene, appearance style, temporal style, overall consistency). Each dimension is scored by a dedicated perception model rather than a single embedding distance, and the official leaderboard aggregates them into quality/semantic splits.

WorldFoundry vendors the official VBench runtime in tree at `worldfoundry/evaluation/tasks/execution/runners/vbench/runtime` and exposes it through `worldfoundry/evaluation/tasks/execution/runners/vbench/run_vbench_official_runner.py`. The runner materializes prompt suites, dispatches the upstream dimension evaluators, and converts the resulting `full_json` outputs into a WorldFoundry scorecard.

Official references:

- Paper: [arxiv.org/abs/2311.17982](https://arxiv.org/abs/2311.17982)
- Project page: [vchitect.github.io/VBench-project](https://vchitect.github.io/VBench-project/)
- Official repository: [Vchitect/VBench](https://github.com/Vchitect/VBench)

## Evaluation protocol

Two execution modes are supported:

- `custom_input`: score an arbitrary directory of generated videos on selected dimensions (no official prompt suite required). Video-only dimensions such as `aesthetic_quality`, `imaging_quality`, `subject_consistency`, `temporal_flickering`, and `motion_smoothness` work directly; text-dependent dimensions need `--prompt` or `--prompt-file`.
- `vbench_standard`: leaderboard-style scoring against the official `VBench_full_info.json` prompt suite. Generated videos must follow the official naming convention `"{prompt}-{index}.mp4"` with five samples per prompt (`index` in `0..4`); the runner preflights prompt-suite coverage before dispatching the upstream evaluator and fails when the materialization is incomplete.

Primary metric: `overall_quality`.

## Data and artifact layout

In-tree paths:

```text
worldfoundry/data/benchmarks/tasks/external/vbench.yaml
worldfoundry/evaluation/tasks/execution/runners/vbench/runtime
```

Stage generated videos and point the runner at them:

```bash
export WORLDFOUNDRY_GENERATED_ARTIFACT_DIR=/path/to/generated_videos
```

For `vbench_standard`, the directory must contain five samples per official prompt:

```text
/path/to/generated_videos/
  "A cat playing piano-0.mp4"
  "A cat playing piano-1.mp4"
  ...
```

Dimension checkpoints are resolved through the shared `vbench_perception_metric_stack` base-model assets; `--load-ckpt-from-local` forces local checkpoint resolution.

## Run the benchmark

Catalog-recorded validation command:

```bash
${WORLDFOUNDRY_UNIFIED_PYTHON} worldfoundry/evaluation/tasks/execution/runners/vbench/run_vbench_official_runner.py run \
  --mode custom_input \
  --dimension aesthetic_quality
```

Score one dimension over a custom video directory:

```bash
${WORLDFOUNDRY_UNIFIED_PYTHON} \
  worldfoundry/evaluation/tasks/execution/runners/vbench/run_vbench_official_runner.py run \
  --mode custom_input \
  --dimension subject_consistency \
  --videos-path "${WORLDFOUNDRY_GENERATED_ARTIFACT_DIR}" \
  --output-dir tmp/vbench/custom \
  --json
```

Import previously computed upstream VBench results instead of re-running the evaluators:

```bash
${WORLDFOUNDRY_UNIFIED_PYTHON} \
  worldfoundry/evaluation/tasks/execution/runners/vbench/run_vbench_official_runner.py run \
  --from-upstream-results /path/to/vbench_full_json_dir \
  --output-dir tmp/vbench/imported \
  --json
```

## Checkpoints and environment variables

- `WORLDFOUNDRY_VBENCH_ROOT`: Optional path to an external VBench checkout; the in-tree runtime is used when unset.
- `WORLDFOUNDRY_GENERATED_ARTIFACT_DIR`: Directory of candidate generated videos.
- `WORLDFOUNDRY_VBENCH_CACHE_DIR`: Cache directory for VBench dimension checkpoints.

This benchmark reuses the shared base-model dependency stack: `vbench_perception_metric_stack`.

## Outputs

The run writes into `--output-dir`:

- `scorecard.json`: WorldFoundry scorecard with the metric values recorded above.
- `raw_metric_table.jsonl`: Metric rows backing the scorecard.
- `upstream_stdout.log`: Captured stdout of the upstream official scorer.
- `upstream_stderr.log`: Captured stderr of the upstream official scorer.

Scorecard primary key: `overall_quality` (leaderboard key `overall_quality`), stored in `scorecard.json`.

## Limitations

- `custom_input` runs on partial dimensions are wiring/development signals, not leaderboard-comparable VBench totals.
- Leaderboard-grade claims require the full official prompt suite, five samples per prompt, and all 16 dimension evaluators with their published checkpoints.
- A local scorecard is not a VBench leaderboard submission; official rankings come from the upstream maintainers.
