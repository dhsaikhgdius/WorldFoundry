## About

**Publisher:** Hao AI Lab, UC San Diego

VideoScience-Bench evaluates whether video generation models understand science: prompts describe real scientific experiments and phenomena, and generated videos are judged on five dimensions — prompt consistency, phenomenon congruency (does the depicted outcome match the true science), correct dynamism, immutability (do invariant properties stay invariant), and spatio-temporal coherence. A VLM judge scores each dimension on a 1-4 rubric; the official weighted overall normalizes to the unit interval as `videoscience_average`.

WorldFoundry integrates VideoScience-Bench with an in-tree runtime: the unified `benchmark-run` entrypoint normalizes caller-provided official result files, and the runtime CLI can drive judge runs over an experiments CSV with a configured judge provider/model.

Official references:

- Paper: [arxiv.org/abs/2512.02942](https://arxiv.org/abs/2512.02942)
- Project page: [huggingface.co/spaces/lmgame/videoscience-bench/blob/main/README.md](https://huggingface.co/spaces/lmgame/videoscience-bench/blob/main/README.md)

## Evaluation protocol

`official-validation` normalizes an official result export. The runtime CLI takes `--experiments-csv`, an `--evaluation-results-dir`, optional `--reference-videos-dir`, and judge configuration (`--judge-provider`, `--judge-model`, `--judge-max-runs`, `--max-frames`, `--judge-fps`); `--ready-only` restricts scoring to experiments whose artifacts are complete.

Primary metric: `videoscience_average`.

| Metric | Meaning | Direction |
| --- | --- | --- |
| `prompt_consistency` | prompt_consistency normalized benchmark score. | Higher is better |
| `phenomenon_congruency` | phenomenon_congruency normalized benchmark score. | Higher is better |
| `correct_dynamism` | correct_dynamism normalized benchmark score. | Higher is better |
| `immutability` | immutability normalized benchmark score. | Higher is better |
| `spatio_temporal_coherence` | spatio_temporal_coherence normalized benchmark score. | Higher is better |
| `videoscience_average` | Official weighted overall score normalized from the 1-4 rubric to the unit interval. | Higher is better |

```text
<evaluation_results_dir>/                                    # judge outputs per experiment
${WORLDFOUNDRY_GENERATED_ARTIFACT_DIR}/                      # generated videos
```

Official benchmark assets come from the source repository and leaderboard space; no Hugging Face dataset is required by the contract entry.

## Run the benchmark

Catalog-recorded validation command:

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id videoscience-bench \
  --mode official-validation \
  --official-results-path <official_results.json> \
  --generated-artifact-dir <generated_videos> \
  --output-dir <out> \
  --json
```

## Checkpoints and environment variables

- `WORLDFOUNDRY_VIDEOSCIENCE_BENCH_ROOT`: Optional override pointing at a local benchmark runtime/repository root.
- `WORLDFOUNDRY_VIDEOSCIENCE_BENCH_RESULTS_PATH`: Default path the importer reads official result exports from when `--official-results-path` is not passed.
- `WORLDFOUNDRY_GENERATED_ARTIFACT_DIR`: Directory containing the candidate generated artifacts to score or import against.

## Outputs

The run writes into `--output-dir`:

- `scorecard.json`: WorldFoundry scorecard with the metric values recorded above.
- `benchmark_contract.json`: Benchmark contract record for the run (inputs, mode, provenance).
- `raw_metric_table.jsonl`: Metric rows backing the scorecard.

Scorecard primary key: `videoscience_average` (leaderboard key `videoscience_average`), stored in `scorecard.json`.

## Limitations

- Scorecards from imported results remain non-leaderboard setup evidence; official runtime execution and judge assets remain pending.
- Full official-run mode requires a configured VLM judge provider/API key.
- Leaderboard parity requires official judge/checkpoint/API assets and normalized upstream result files.
