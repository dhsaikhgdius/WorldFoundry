## About

MiKASA-Robo is a benchmark of memory-intensive robotic manipulation tasks. Its task families explicitly require remembering past observations — remembering colors and shapes, shell games with hidden objects, rotation histories, moving-object interception, and color-sequence recall — so agents that only react to the current frame cannot solve them.

WorldFoundry integrates MiKASA-Robo with an in-tree closed-loop simulator adapter at `worldfoundry/evaluation/tasks/embodied/simulators/mikasa/` (aliases `mikasa-robo`, `mikasa_robo`) plus the shared official result normalizer for caller-provided rollout dumps. The catalog verification status is `normalizer_only`.

Official references:

- Official source reference: [CognitiveAISystems/MIKASA-Robo](https://github.com/CognitiveAISystems/MIKASA-Robo)
- License: upstream terms (see repository)
- The catalog records no separate paper URL for this benchmark id.

## In-tree integration

- Catalog: `worldfoundry/data/benchmarks/catalog/embodied/mikasa.yaml`
- Task manifest: `worldfoundry/data/benchmarks/tasks/external/mikasa.yaml`
- Runtime profile: `worldfoundry/data/benchmarks/runtime_profiles/official/mikasa.yaml`
- Simulator adapter: `worldfoundry/evaluation/tasks/embodied/simulators/mikasa/`
- Closed-loop eval config: `worldfoundry/data/benchmarks/eval_configs/embodied/mikasa/eval.yaml`
- Result normalizer: `worldfoundry.evaluation.tasks.embodied.normalizer` (track `vla`)

## Evaluation protocol and result layout

For result import, the embodied normalizer accepts JSON, JSONL, CSV, TSV, and `result.txt`-style logs. Rows are matched on numeric fields such as `success`, `success_rate`, `task_success`, `episode_success`, and `reward`; booleans and percent strings are coerced to unit-interval floats.

The bundled eval config rolls out 32 memory tasks — the `RememberColor{3,5,9}-v0` and `RememberShape{3,6,9}-v0` families, `ShellGame{Touch,Push,Pick}-v0`, `RotateLenient`/`RotateStrict` variants, `Intercept`/`InterceptGrab` speed variants, `TakeItBack-v0`, `BunchOfColors`/`SeqOfColors`/`ChainOfColors` recall families, and `RememberShapeAndColor` combinations — at 256×256 render resolution, 50 episodes per task, against an external policy server at `ws://localhost:8000`.

## Metrics

Primary metric (scorecard key): `success_rate`.

| Metric | Meaning |
| --- | --- |
| `success_rate` | Share of rollouts completed successfully; primary leaderboard value. |
| `task_success` | Per-task success aggregated across episodes. |
| `episode_success` | Per-episode binary success. |
| `reward` | Cumulative episode reward. |

Success metrics are normalized via the shared registry (`percent_or_fraction_to_unit`). No video-generation metrics apply.

## Preparation and environment

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_MIKASA_ROOT=/path/to/MIKASA-Robo
export WORLDFOUNDRY_MIKASA_RESULTS_PATH=/path/to/mikasa_results.json
```

Closed-loop rollouts require the MiKASA-Robo runtime, task assets, and a policy checkpoint served over WebSocket (catalog `required_assets`).

Verify runtime wiring:

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile mikasa \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/mikasa.yaml \
  --output-dir tmp/worldfoundry_preflight/mikasa \
  --json
```

## Import official results (official-validation)

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id mikasa \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_MIKASA_RESULTS_PATH}" \
  --output-dir tmp/mikasa/official-validation \
  --json
```

This routes through the embodied `vla`-track normalizer in-process; no simulator code is executed.

## Closed-loop rollouts (native simulator)

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/mikasa/eval.yaml \
  --output-dir tmp/mikasa/embodied-run \
  --json
```

`--server-url`, `--shard-id`/`--num-shards`, and `--no-docker` are supported by the `embodied run` entry point.

## Outputs

- `scorecard.json`: WorldFoundry scorecard; leaderboard block keyed by `success_rate`.
- `raw_results.jsonl`: extracted raw result rows.
- `evaluation/summary.json`: aggregated per-metric statistics.
- `evaluation/per_sample_metrics.jsonl`: normalized per-episode rows.

## What this page does not claim

- Catalog status is `normalizer_only` with `leaderboard_valid: false` and `official_benchmark_verified: false`. Imported numbers are normalized copies of caller-provided results, not officially reproduced leaderboard values.
- The MiKASA-Robo runtime, task assets, and policy checkpoints are not bundled; closed-loop rollouts require external staging plus a policy server. No local GPU rollout evidence is claimed.
- Full leaderboard parity is not claimed until official rollouts are executed and imported (catalog blocker).
