## 简介

**发表机构：** Soongsil University（崇实大学）与 Chung-Ang University（中央大学，韩国）

LIBERO-Para 诊断视觉-语言-动作模型的指令改写鲁棒性。它构建在 LIBERO-Goal 之上——所有任务共享同一初始状态，指令成为唯一任务线索——并独立变换动作表达与物体指称（43 个类别共 4,092 条仅用于评测的改写指令，含 30 种组合类型）。官方同时提出 PRIDE 指标，用语义与句法因素按改写难度加权成功率。

WorldFoundry 以官方结果 runner 集成 LIBERO-Para，`HAI-Lab/LIBERO-Para` 数据集作为就位资产跟踪；上游 rollout 导出被归一化为统一 scorecard。

官方参考：

- Paper: [huggingface.co/papers/2603.28301](https://huggingface.co/papers/2603.28301)
- 官方仓库: [cau-hai-lab/LIBERO-Para](https://github.com/cau-hai-lab/LIBERO-Para)
- License: `mit`

## 评测协议

WorldFoundry 通过统一的结果导入路径集成该 benchmark：`worldfoundry-eval zoo benchmark-run --mode official-validation` 把调用方提供的官方结果导出（JSON/CSV rollout 汇总）归一化为 WorldFoundry scorecard，不执行模拟器。模拟器执行、策略加载与 rollout 采集仍是使用官方工具完成的显式上游步骤。

主指标是 `success_rate`。

| Metric | 含义 | 方向 |
| --- | --- | --- |
| `success_rate` | 评测 rollout 上的主成功率（逐 episode 成功比例）。 | 越高越好 |
| `paraphrase_success_rate` | 改写指令下的成功率。 | 越高越好 |
| `language_generalization_success` | 语言变体分割上的成功率聚合。 | 越高越好 |
| `task_success` | 按任务聚合的成功率。 | 越高越好 |
| `action_accuracy` | 相对参考动作的离线动作预测准确率。 | 越高越好 |

## 运行评测

目录 manifest 记录的 validation 命令：

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id libero-para \
  --mode official-validation \
  --official-results-path <official_results.json> \
  --output-dir <out> \
  --json
```

## 权重与环境变量

- `WORLDFOUNDRY_LIBERO_PARA_ROOT`: 可选覆盖项，指向本地 benchmark runtime / 仓库根目录。
- `WORLDFOUNDRY_LIBERO_PARA_RESULTS_PATH`: 未显式传 `--official-results-path` 时，导入器默认从该路径读取官方结果导出文件。
- `WORLDFOUNDRY_LIBERO_PARA_DATASET_ROOT`: 本地官方数据集根目录。

该 benchmark 复用共享 base-model 依赖栈：`libero_para_source_assets`, `libero_para_dataset_assets`。

## 输出文件

运行会在 `--output-dir` 下写出：

- `scorecard.json`: WorldFoundry 统一 scorecard，记录上表中的指标值。
- `benchmark_contract.json`: 本次运行的 benchmark contract 记录（输入、模式、来源信息）。
- `raw_metric_table.jsonl`: 支撑 scorecard 的原始 metric 行。
- `raw_results.jsonl`: 从官方结果导出解析出的归一化行。

Scorecard 主键：`success_rate`（leaderboard key `success_rate`），写入 `scorecard.json`。

## 边界与限制

- 本工作区尚未通过官方 LIBERO-Para rollout 执行产生 leaderboard 证据。
- 改写分割映射与结果导入字段需在真实上游输出上验证。
- 导入的 scorecard 是集成证据，不是 leaderboard 提交。
