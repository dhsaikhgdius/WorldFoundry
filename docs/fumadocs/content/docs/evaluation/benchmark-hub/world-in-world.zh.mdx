## 简介

**发表机构：** Johns Hopkins University（约翰斯·霍普金斯大学，联合 PKU、Princeton、MIT、Harvard）

World-in-World（ICLR 2026 Oral）在贴近真实智能体-环境交互的闭环中评测生成式世界模型，把任务成功率置于视觉质量之上。它提供统一的在线规划策略与标准化动作 API，覆盖四个闭环环境：主动识别（Active Recognition）、主动具身 QA（A-EQA）、图像目标导航（IGNav）与机器人操作。核心发现：仅有视觉质量不能保证任务成功（可控性更重要）；动作-观测后训练比升级视频生成器更有效；推理时算力可显著提升闭环表现。

WorldFoundry 以结果导入器集成 World-in-World：把调用方提供的任务摘要归一化到指标面，捆绑资产支持解析与覆盖率检查。

官方参考：

- Paper: [arxiv.org/abs/2510.18135](https://arxiv.org/abs/2510.18135)
- 项目主页: [world-in-world.github.io](https://world-in-world.github.io/)

## 评测协议

仓内 runner 仅导入结果摘要：传 `--official-results-path`（或 `WORLDFOUNDRY_WORLD_IN_WORLD_RESULTS_PATH`），可用 `--task` 与 `--exp-id` 限定范围。闭环环境、规划器、worker 与任务 scorer 都在上游执行——不在 WorldFoundry 内。

主指标是 `world_in_world_average`。

| Metric | 含义 | 方向 |
| --- | --- | --- |
| `active_recognition_success_rate` | 主动识别闭环任务成功率。 | 越高越好 |
| `image_goal_navigation_success_rate` | 图像目标导航成功率。 | 越高越好 |
| `image_goal_navigation_spl` | 图像目标导航按路径长度加权的成功率（SPL）。 | 越高越好 |
| `active_embodied_qa_score` | 主动具身 QA 的答案得分。 | 越高越好 |
| `active_embodied_qa_spl` | 主动具身 QA 探索过程的 SPL。 | 越高越好 |
| `robotic_manipulation_success_rate` | 机器人操作任务成功率。 | 越高越好 |
| `interaction_trace_consistency` | 世界模型预测交互轨迹的一致性。 | 越高越好 |
| `world_in_world_average` | 可用闭环任务指标的均值。 | 越高越好 |

## 运行评测

目录 manifest 记录的 validation 命令：

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id world-in-world \
  --mode official-validation \
  --official-results-path <official_results.json> \
  --generated-artifact-dir <generated_videos> \
  --output-dir <out> \
  --json
```

## 权重与环境变量

- `WORLDFOUNDRY_WORLD_IN_WORLD_RESULTS_PATH`: 未显式传 `--official-results-path` 时，导入器默认从该路径读取官方结果导出文件。
- `WORLDFOUNDRY_GENERATED_ARTIFACT_DIR`: 存放待评测生成产物（候选视频/rollout）的目录。

## 输出文件

运行会在 `--output-dir` 下写出：

- `scorecard.json`: WorldFoundry 统一 scorecard，记录上表中的指标值。
- `benchmark_contract.json`: 本次运行的 benchmark contract 记录（输入、模式、来源信息）。
- `raw_metric_table.jsonl`: 支撑 scorecard 的原始 metric 行。

Scorecard 主键：`world_in_world_average`（leaderboard key `world_in_world_average`），写入 `scorecard.json`。

## 边界与限制

- 闭环 rollout 生成、环境执行与官方任务打分完全在本导入器之外。
- 导入的摘要不构成官方 benchmark / leaderboard 证据。
- 覆盖率检查只验证摘要结构，不验证上游结果的产生过程。
