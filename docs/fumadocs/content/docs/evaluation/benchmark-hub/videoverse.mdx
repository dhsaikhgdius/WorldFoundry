## About

**Publisher:** OPPO Research Institute (with Sun Yat-sen University & HK PolyU)

VideoVerse asks how far a text-to-video generator is from a world model. Each of its 300 prompts is decomposed into ordered events with binary evaluation questions spanning ten dimensions, grouped into families such as QA accuracy, event coverage, temporal causality, world-knowledge consistency, and static/dynamic scene consistency. Judging combines an event-LCS (longest-common-subsequence) check over detected event order with per-question verification.

WorldFoundry runs the VideoVerse judge in tree — Gemini, URL, or local VLM backend — and normalizes `eval_res.json` through the official event-LCS and verification-check logic. Official prompt manifests are bundled in tree; the runner validates prompt/result/video coverage and records whether the canonical 300-prompt suite is complete.

Official references:

- Paper: [arxiv.org/abs/2510.08398](https://arxiv.org/abs/2510.08398)
- Project page: [www.naptmn.cn/Homepage_of_VideoVerse](https://www.naptmn.cn/Homepage_of_VideoVerse/)
- Official repository: [Zeqing-Wang/VideoVerse](https://github.com/Zeqing-Wang/VideoVerse)

## Evaluation protocol

`--run-official` judges generated videos against the bundled prompt manifests (`prompts_of_VideoVerse.json`, decomposed variant), using the Gemini backend by default (`GEMINI_API_KEY`). `official-validation` normalizes an existing `eval_res.json`. Use `--prompt-manifest` / `--decomposed-prompt-manifest` only for non-standard prompt assets; `--strict` enforces full-suite coverage.

Primary metric: `videoverse_average`.

| Metric | Meaning | Direction |
| --- | --- | --- |
| `qa_accuracy` | VideoVerse binary/question-answer judging accuracy. | Higher is better |
| `event_coverage` | Coverage of required events. | Higher is better |
| `temporal_causality` | Temporal causality consistency score. | Higher is better |
| `world_knowledge_consistency` | World-knowledge consistency score. | Higher is better |
| `static_scene_consistency` | Static scene consistency score. | Higher is better |
| `dynamic_event_consistency` | Dynamic event consistency score. | Higher is better |
| `videoverse_average` | Mean over available VideoVerse score families. | Higher is better |

## Run the benchmark

Catalog-recorded validation command:

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id videoverse \
  --mode official-validation \
  --official-results-path <official_results.json> \
  --generated-artifact-dir <generated_videos> \
  --output-dir <out> \
  --json
```

## Checkpoints and environment variables

- `WORLDFOUNDRY_VIDEOVERSE_RESULTS_PATH`: Default path the importer reads official result exports from when `--official-results-path` is not passed.
- `WORLDFOUNDRY_GENERATED_ARTIFACT_DIR`: Directory containing the candidate generated artifacts to score or import against.
- `GEMINI_API_KEY`: Required for the Gemini judge backend (WORLDFOUNDRY_VIDEOVERSE_GEMINI_API_KEY also accepted).

This benchmark reuses the shared base-model dependency stack: `videoverse_dataset_assets`.

## Outputs

The run writes into `--output-dir`:

- `scorecard.json`: WorldFoundry scorecard with the metric values recorded above.
- `benchmark_contract.json`: Benchmark contract record for the run (inputs, mode, provenance).
- `raw_metric_table.jsonl`: Metric rows backing the scorecard.
- `eval_res.json`
- `judge_responses.jsonl`

Scorecard primary key: `videoverse_average` (leaderboard key `videoverse_average`), stored in `scorecard.json`.

## Limitations

- Framework integration is complete when strict full-suite coverage passes and all seven metric families are available.
- Leaderboard parity still requires source-audited Gemini/API judge execution and submission-protocol evidence for the complete official suite.
- Partial-prompt judge runs are development signals, not official VideoVerse numbers.
