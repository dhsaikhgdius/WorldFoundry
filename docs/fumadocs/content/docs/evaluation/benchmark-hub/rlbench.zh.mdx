## 关于

RLBench 是构建在 CoppeliaSim 与 PyRep 上的大规模机器人学习基准。它提供 100+ 个手工设计的桌面操作任务（Franka Panda 机械臂）、示范生成与按 rollout 成功率的标准化评测，被广泛用于多任务、少样本与视觉操作研究。

WorldFoundry 通过仓内闭环仿真适配器 `worldfoundry/evaluation/tasks/embodied/simulators/rlbench/` 以及共享官方结果归一化器集成 RLBench。catalog 校验状态为 `normalizer_only`：结果导入已验证，仿真执行需要外部 CoppeliaSim/PyRep 运行时。

- 论文：[arXiv:1909.12271](https://arxiv.org/abs/1909.12271)
- 项目主页：[sites.google.com/corp/view/rlbench](https://sites.google.com/corp/view/rlbench)
- 官方仓库：[stepjam/RLBench](https://github.com/stepjam/RLBench)（固定 `02720bba`）

## 仓内路径

- Catalog：`worldfoundry/data/benchmarks/catalog/embodied/rlbench.yaml`
- 任务清单：`worldfoundry/data/benchmarks/tasks/external/rlbench.yaml`
- 运行时 profile：`worldfoundry/data/benchmarks/runtime_profiles/official/rlbench.yaml`
- 仿真适配器：`worldfoundry/evaluation/tasks/embodied/simulators/rlbench/`
- 闭环 eval config：`worldfoundry/data/benchmarks/eval_configs/embodied/rlbench/eval.yaml`
- 结果归一化器：`worldfoundry.evaluation.tasks.embodied.normalizer`（track `vla`）

## 评测协议与数据布局

结果导入侧，embodied normalizer 接受 JSON、JSONL、CSV、TSV 及 `result.txt` 风格日志。行记录按 `success`、`success_rate`、`task_success`、`episode_success`、`reward`、`normalized_return` 等数值字段匹配；布尔值与百分比字符串会被强制转换为 [0,1] 浮点数。

内置 eval config rollout 18 个桌面任务（从 `reach_target`、`pick_up_cup` 到 `stack_cups`、`light_bulb_in`、`take_lid_off_saucepan`），256px 渲染、最长 200 步、每任务 25 个 episode，由 `ws://localhost:8000` 上的外部 policy server 驱动。

## 指标

主指标（scorecard 主键）：`success_rate`。

| 指标 | 含义 |
| --- | --- |
| `success_rate` | 成功完成的 rollout 占比；leaderboard 主值。 |
| `task_success` | 按任务聚合的成功率。 |
| `episode_success` | 单 episode 的二值成功。 |
| `reward` | episode 累计奖励。 |
| `normalized_return` | 有上报时，按任务参考区间归一化的 return。 |

成功类指标经共享 registry 的 `percent_or_fraction_to_unit` 归一化；不涉及视频生成类指标。

## 准备命令与环境变量

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_RLBENCH_RESULTS_PATH=/path/to/rlbench_results.json
```

运行时 profile 标记 `needs_new_env: true`：RLBench 需要 CoppeliaSim/PyRep 组合环境，profile 只记录环境变量与任务清单，不启动仿真器。闭环 rollout 还需要 RLBench 任务 assets 与通过 WebSocket 提供动作的策略 checkpoint。

校验运行时接线：

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile rlbench \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/rlbench.yaml \
  --output-dir tmp/worldfoundry_preflight/rlbench \
  --json
```

## 导入官方结果（official-validation）

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id rlbench \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_RLBENCH_RESULTS_PATH}" \
  --output-dir tmp/rlbench/official-validation \
  --json
```

该路径在进程内走 embodied `vla` track normalizer，不执行任何仿真代码。

## 闭环 rollout（原生仿真器）

在 CoppeliaSim/PyRep 已安装、policy server 已启动的前提下：

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/rlbench/eval.yaml \
  --output-dir tmp/rlbench/embodied-run \
  --json
```

`embodied run` 入口支持 `--server-url`、`--shard-id`/`--num-shards`、`--no-docker`。

## 输出

- `scorecard.json`：WorldFoundry scorecard；leaderboard 块以 `success_rate` 为主键。
- `raw_results.jsonl`：提取的原始结果行。
- `evaluation/summary.json`：按指标聚合的统计。
- `evaluation/per_sample_metrics.jsonl`：归一化后的逐 episode 行。

## 不能声称的边界

- catalog 状态为 `normalizer_only`，`leaderboard_valid: false`、`official_benchmark_verified: false`。导入的数字是调用方结果的归一化副本，不是官方复现的 leaderboard 值。
- CoppeliaSim 与 PyRep 未安装在默认 WorldFoundry 环境中；闭环 rollout 需要外部仿真运行时并运行 policy server。本页不声称任何本地 rollout 证据。
- catalog blocker：CoppeliaSim/PyRep 运行时验证与任务清单映射完成之前，不达到 integrated 状态。
