## About

SimplerEnv provides simulated evaluation environments that track real-robot benchmark performance for manipulation policies. Built on ManiSkill2/SAPIEN, it reproduces Google Robot and WidowX/Bridge evaluation setups in simulation so that policies such as RT-1 or Octo can be compared without physical robots, with success rates designed to correlate with real-world evaluations.

WorldFoundry integrates SimplerEnv with an in-tree closed-loop simulator adapter at `worldfoundry/evaluation/tasks/embodied/simulators/simpler/` (aliases `simpler`, `simplerenv`, `simpler_env`) plus the shared official result normalizer for caller-provided rollout dumps. The catalog verification status is `normalizer_only`.

- Result normalizer: `worldfoundry.evaluation.tasks.embodied.normalizer` (track `vla`)

## Evaluation protocol and result layout

For result import, the embodied normalizer accepts JSON, JSONL, CSV, TSV, and `result.txt`-style logs. Rows are matched on numeric fields such as `success`, `success_rate`, `task_success`, `episode_success`, and `reward`; booleans and percent strings are coerced to unit-interval floats.

The bundled `google_robot.yaml` config chains six Google Robot tasks (`google_robot_pick_coke_can`, `google_robot_pick_object`, `google_robot_move_near`, `google_robot_open_drawer`, `google_robot_close_drawer`, `google_robot_place_in_closed_drawer`) with 24 episodes per task, against an external policy server at `ws://localhost:8000`; `widowx.yaml` covers the WidowX/Bridge embodiment.

## Metrics

Primary metric (scorecard key): `success_rate`.

| Metric | Meaning |
| --- | --- |
| `success_rate` | Share of rollouts completed successfully; primary leaderboard value. |
| `task_success` | Per-task success aggregated across episodes. |
| `episode_success` | Per-episode binary success. |
| `reward` | Cumulative episode reward. |

Success metrics are normalized via the shared registry (`percent_or_fraction_to_unit`). No video-generation metrics apply.

## Preparation and environment

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_SIMPLERENV_RESULTS_PATH=/path/to/simpler_env_results.json
```

Closed-loop rollouts require the official SimplerEnv repository checkout (cached at `cache/vla_va_wam/repos/simpler-env--SimplerEnv`), the ManiSkill2/SAPIEN simulator stack, the selected robot embodiment assets, and a policy checkpoint served over WebSocket (catalog `requires`).

Verify runtime wiring:

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile simpler-env \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/simpler-env.yaml \
  --output-dir tmp/worldfoundry_preflight/simpler-env \
  --json
```

## Import official results (official-validation)

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id simpler-env \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_SIMPLERENV_RESULTS_PATH}" \
  --output-dir tmp/simpler-env/official-validation \
  --json
```

This routes through the embodied `vla`-track normalizer in-process; no simulator code is executed.

## Closed-loop rollouts (native simulator)

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/simpler-env/google_robot.yaml \
  --output-dir tmp/simpler-env/embodied-run \
  --json
```

Use `widowx.yaml` for the WidowX/Bridge embodiment. `--server-url`, `--shard-id`/`--num-shards`, and `--no-docker` are supported.

## Outputs

- `scorecard.json`: WorldFoundry scorecard; leaderboard block keyed by `success_rate`.
- `raw_results.jsonl`: extracted raw result rows.
- `evaluation/summary.json`: aggregated per-metric statistics.
- `evaluation/per_sample_metrics.jsonl`: normalized per-episode rows.

## What this page does not claim

- Catalog status is `normalizer_only` with `leaderboard_valid: false` and `official_benchmark_verified: false`. Imported numbers are normalized copies of caller-provided results, not officially reproduced leaderboard values.
- The ManiSkill2/SAPIEN stack, embodiment assets, and policy checkpoints are not bundled; closed-loop rollouts require external staging plus a policy server. No local GPU rollout evidence is claimed.
- Official SimplerEnv simulator rollouts, policy wrappers, and result import mapping must be validated before integrated status (catalog blocker).
