## 关于

LIBERO-Pro 用程序化变体任务实例扩展 LIBERO 操作基准——例如替换目标物体（内置 config 运行 `libero_spatial_with_mug`）——检验视觉-语言-动作策略是否能泛化到训练中未见过的物体组合。

WorldFoundry 通过仓内闭环仿真适配器 `worldfoundry/evaluation/tasks/embodied/simulators/libero_pro/` 以及共享官方结果归一化器集成 LIBERO-Pro。catalog 校验状态为 `normalizer_only`：结果导入已验证，完整官方 rollout 需要 LIBERO-Pro 运行时、任务 assets 与策略 checkpoint。

官方来源：

- 官方仓库：[Lifelong-Robot-Learning/LIBERO](https://github.com/Lifelong-Robot-Learning/LIBERO)
- 许可：MIT
- catalog 未记录 LIBERO-Pro 独立的论文 URL。

## 仓内路径

- Catalog：`worldfoundry/data/benchmarks/catalog/embodied/libero-pro.yaml`
- 任务清单：`worldfoundry/data/benchmarks/tasks/external/libero-pro.yaml`
- 运行时 profile：`worldfoundry/data/benchmarks/runtime_profiles/official/libero-pro.yaml`
- 仿真适配器：`worldfoundry/evaluation/tasks/embodied/simulators/libero_pro/`
- 闭环 eval config：`worldfoundry/data/benchmarks/eval_configs/embodied/libero-pro/eval.yaml`
- 结果归一化器：`worldfoundry.evaluation.tasks.embodied.normalizer`（track `vla`）

## 评测协议与数据布局

结果导入侧，embodied normalizer 接受 JSON、JSONL、CSV、TSV 及 `result.txt` 风格日志。行记录按 `success`、`success_rate`、`task_success`、`episode_success`、`action_accuracy` 等数值字段匹配；布尔值与百分比字符串会被强制转换为 [0,1] 浮点数。

内置 eval config 以 seed 7 运行 `libero_spatial_with_mug` 套件，仿真器预热 10 步，最多 10 个任务、每任务 50 个 episode，并要求 `ws://localhost:8000` 上有外部 policy server。

## 指标

主指标（scorecard 主键）：`success_rate`。

| 指标 | 含义 |
| --- | --- |
| `success_rate` | 成功完成的 rollout 占比；leaderboard 主值。 |
| `task_success` | 按任务聚合的成功率。 |
| `episode_success` | 单 episode 的二值成功。 |
| `action_accuracy` | 有上报时，预测动作与参考动作的一致度。 |

成功类指标经共享 registry 的 `percent_or_fraction_to_unit` 归一化；不涉及视频生成类指标。

## 准备命令与环境变量

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_LIBERO_PRO_ROOT=/path/to/LIBERO-Pro
export WORLDFOUNDRY_LIBERO_PRO_RESULTS_PATH=/path/to/libero_pro_results.json
```

闭环 rollout 需要 LIBERO-Pro 运行时、任务 assets，以及通过 WebSocket 提供动作的策略 checkpoint（catalog `required_assets`）。

不启动仿真器、仅校验运行时接线：

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile libero-pro \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/libero-pro.yaml \
  --output-dir tmp/worldfoundry_preflight/libero-pro \
  --json
```

## 导入官方结果（official-validation）

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id libero-pro \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_LIBERO_PRO_RESULTS_PATH}" \
  --output-dir tmp/libero-pro/official-validation \
  --json
```

该路径在进程内走 embodied `vla` track normalizer，不执行任何仿真代码。

## 闭环 rollout（原生仿真器）

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/libero-pro/eval.yaml \
  --output-dir tmp/libero-pro/embodied-run \
  --json
```

`embodied run` 入口支持 `--server-url`、`--shard-id`/`--num-shards`、`--no-docker`。

## 输出

- `scorecard.json`：WorldFoundry scorecard；leaderboard 块以 `success_rate` 为主键。
- `raw_results.jsonl`：提取的原始结果行。
- `evaluation/summary.json`：按指标聚合的统计。
- `evaluation/per_sample_metrics.jsonl`：归一化后的逐 episode 行。

## 不能声称的边界

- catalog 状态为 `normalizer_only`，`leaderboard_valid: false`、`official_benchmark_verified: false`。导入的数字是调用方结果的归一化副本，不是官方复现的 leaderboard 值。
- LIBERO-Pro 任务 assets、仿真运行时、策略 checkpoint 均未随仓库分发；闭环 rollout 需要外部安装并运行 policy server。本页不声称任何本地 GPU rollout 证据。
- catalog blocker：官方 rollout 执行并导入之前，不声称完整 leaderboard 对齐。
