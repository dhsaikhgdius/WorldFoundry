## About

**Publisher:** Tsinghua University (with NTU & Waterloo)

WorldReasonBench reframes video-generation evaluation as world-state prediction: given an initial state and an action, can a model generate a future video whose state evolution stays physically, socially, logically, and informationally consistent? It contains 436 curated cases with structured QA annotations across four reasoning dimensions and 22 subcategories. Evaluation is two-part: Process-aware Reasoning Verification (structured QA plus reasoning-phase diagnostics that catch temporal and causal failures) and Multi-dimensional Quality Assessment (reasoning quality, temporal consistency, visual aesthetics). The companion WorldRewardBench adds ~6K expert preference pairs for point-wise/pair-wise reward-model evaluation.

WorldFoundry hosts the protocol runtime in tree with external judge assets: an OpenAI-compatible multimodal judge scores QA and quality dimensions.

## Evaluation protocol

Select the protocol with `--protocol` and supply QA/pair files (`--qa-json`, `--pairs-json`) plus judge access (`--base-url`, `--api-key`, `--model`, `--judge-model`). The primary scorecard key `score_pr` geometrically combines QA accuracy with the dynamic reasoning score; `reasoning_gap` (static outcome minus dynamic reasoning, lower is better) flags outcome hacking. `--official-results-path` normalizes existing official result directories.

Primary metric: `score_pr`.

| Metric | Meaning | Direction |
| --- | --- | --- |
| `score_pr` | Geometric combination of QA accuracy and dynamic reasoning score. | Higher is better |
| `qa_accuracy` | Structured QA accuracy over ground-truth world-state questions. | Higher is better |
| `state_score` | Correctness of the final predicted world state. | Higher is better |
| `process_score` | Reasoning-phase diagnostic score over the state-evolution process. | Higher is better |
| `fidelity_score` | Content fidelity of the generated evolution. | Higher is better |
| `mechanism_score` | Correctness of the causal mechanism driving the evolution. | Higher is better |
| `static_outcome_score` | Outcome score judged from static (final-state) evidence only. | Higher is better |
| `dynamic_reasoning_score` | Reasoning score judged from the full temporal evolution. | Higher is better |
| `reasoning_gap` | Static outcome score minus dynamic reasoning score; lower values indicate less outcome hacking. | Lower is better |
| `pointwise_score` | Point-wise quality score used for reward-model evaluation. | Higher is better |
| `reasoning_correctness` | Multi-dimensional assessment: reasoning quality. | Higher is better |
| `content_fidelity` | Multi-dimensional assessment: temporal/content consistency. | Higher is better |
| `visual_aesthetics` | Multi-dimensional assessment: visual aesthetics. | Higher is better |
| `pointwise_spearman` | Spearman correlation of point-wise scores with expert rankings. | Higher is better |
| `induced_pairwise_accuracy` | Pairwise preference accuracy induced from point-wise scores. | Higher is better |
| `pairwise_accuracy_with_ties` | Pairwise preference accuracy counting tied pairs. | Higher is better |
| `pairwise_accuracy_without_ties` | Pairwise preference accuracy excluding tied pairs. | Higher is better |

## Checkpoints and environment variables

- `WORLDFOUNDRY_WORLDREASONBENCH_ROOT`: Optional override pointing at a local benchmark runtime/repository root.
- `WORLDFOUNDRY_WORLDREASONBENCH_RESULTS_PATH`: Default path the importer reads official result exports from when `--official-results-path` is not passed.
- `WORLDFOUNDRY_GENERATED_ARTIFACT_DIR`: Directory containing the candidate generated artifacts to score or import against.

## Outputs

The run writes into `--output-dir`:

- `scorecard.json`: WorldFoundry scorecard with the metric values recorded above.
- `raw_metric_table.jsonl`: Metric rows backing the scorecard.
- `protocol_results.json`
- `benchmark_contract.json`: Benchmark contract record for the run (inputs, mode, provenance).

Scorecard primary key: `score_pr` (leaderboard key `score_pr`), stored in `scorecard.json`.

## Limitations

- Full official QA, pointwise, and pairwise judge runs have not been executed through this integration.
- The upstream README prohibits redistribution, modification, and commercial use without approval; treat assets as restricted.
- Judge-dependent scores vary with the configured multimodal judge; only the official judge configuration is paper-comparable.
