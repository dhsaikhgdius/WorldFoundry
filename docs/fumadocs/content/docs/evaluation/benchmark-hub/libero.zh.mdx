## 简介

**发表机构：** The University of Texas at Austin（德克萨斯大学奥斯汀分校，联合清华大学与 Sony AI）

LIBERO（NeurIPS 2023 D&B）评测终身机器人学习中的知识迁移：四个任务套件——LIBERO-Spatial、LIBERO-Object、LIBERO-Goal 与 LIBERO-100——在 robosuite/MuJoCo 桌面环境中考察操作策略跨任务迁移陈述性与程序性知识的能力。它已成为视觉-语言-动作（VLA）模型事实上的评测标准。

WorldFoundry 支持两条路径：经 `worldfoundry.evaluation.tasks.embodied.normalizer` 的 normalizer-first scorecard（官方结果导入），以及通过 `worldfoundry-eval embodied run` 接线的原生闭环执行。LIBERO 数据集快照（`yifengzhu-hf/LIBERO-datasets`、`lerobot/libero`）与上游仓库均作为就位资产跟踪。

官方参考：

- Paper: [arxiv.org/abs/2306.03310](https://arxiv.org/abs/2306.03310)
- 项目主页: [libero-project.github.io](https://libero-project.github.io/)
- 官方仓库: [Lifelong-Robot-Learning/LIBERO](https://github.com/Lifelong-Robot-Learning/LIBERO)
- License: `mit`

## 评测协议

结果导入通过 `--official-results-path` / `WORLDFOUNDRY_LIBERO_RESULTS_PATH` 归一化官方 eval_result 树或结构化导出。闭环执行需要上游模拟器 runtime、任务套件资产与所选上游评测脚本对应的策略权重。

主指标是 `success_rate`。

| Metric | 含义 | 方向 |
| --- | --- | --- |
| `success_rate` | 评测 rollout 上的主成功率（逐 episode 成功比例）。 | 越高越好 |
| `task_success` | 按任务聚合的成功率。 | 越高越好 |
| `episode_success` | 逐 episode 成功指示的聚合值。 | 越高越好 |
| `action_accuracy` | 相对参考动作的离线动作预测准确率。 | 越高越好 |

## 运行评测

目录 manifest 记录的 validation 命令：

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id libero \
  --mode official-validation \
  --official-results-path <official_results.json> \
  --output-dir <out> \
  --json
```

## 权重与环境变量

- `WORLDFOUNDRY_LIBERO_ROOT`: 可选覆盖项，指向本地 benchmark runtime / 仓库根目录。
- `WORLDFOUNDRY_LIBERO_RESULTS_PATH`: 未显式传 `--official-results-path` 时，导入器默认从该路径读取官方结果导出文件。

该 benchmark 复用共享 base-model 依赖栈：`libero_source_assets`, `libero_dataset_assets`。

## 输出文件

运行会在 `--output-dir` 下写出：

- `scorecard.json`: WorldFoundry 统一 scorecard，记录上表中的指标值。
- `run_manifest.json`: 本次 rollout 运行的 manifest。
- `results.jsonl`: 逐 episode 的 rollout 记录。
- `metrics/summary.json`: 本次运行的聚合指标摘要。

Scorecard 主键：`success_rate`（leaderboard key `success_rate`），写入 `scorecard.json`。

## 边界与限制

- 完整 leaderboard 对齐需要带模拟器资产与策略权重的 LIBERO/OpenVLA 对齐运行记录。
- 导入的 scorecard 是集成证据，不是 leaderboard 提交。
- 套件选择与评测随机种子必须匹配上游协议才可比较。
