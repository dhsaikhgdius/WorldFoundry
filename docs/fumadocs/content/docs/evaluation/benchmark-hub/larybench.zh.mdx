## 简介

**发表机构：** Meituan（美团 LongCat 团队）

LARYBench 度量视频/世界模型的 latent action 表征捕获了多少真实机器人动作信息。流程分三阶段：先从所选表征模型对机器人数据集（CALVIN、VLABench、AgiBot-Beta、RoboCOIN）**抽取** latent action，再用**分类**探针（预测离散动作类别，按 top-1 准确率与 F1 打分）与**回归**探针（预测连续机器人动作，按 seen / unseen 验证集 MSE 打分）检验。

WorldFoundry 在仓内内置 LARYBench 各阶段驱动（`cli.py`、`extract.py`、`classification.py`、`regression.py`）：抽取阶段把一张元数据表按所选 GPU 分片并合并结果 CSV；分类阶段每 GPU 一个本地进程；回归阶段用 Accelerate 跨 `CUDA_VISIBLE_DEVICES` 执行。已有官方输出可在不加载数据集与权重的情况下直接归一化。

- Paper: [arxiv.org/abs/2604.11689](https://arxiv.org/abs/2604.11689)

## 评测协议

导入模式用 `--stage classify` / `--stage regress` 归一化官方 `classification_summary.json` 或 `best_result.json`。完整运行需把所选 LARYBench 数据分片放到 `DATA_DIR`、元数据放到 `LARY_METADATA_DIR`、已抽取 latent action 放到 `LARY_LA_DIR`、表征模型权重放到 `MODEL_DIR`，然后依次执行 `extract` → `classify`（需 `--dim`、`--classes`）→ `regress`（支持 `--action-mode absolute|delta` 及逐数据集统计 JSON）。

主指标是 `extraction_coverage`。

| Metric | 含义 | 方向 |
| --- | --- | --- |
| `extraction_coverage` | 元数据行中成功抽取 latent action 的比例。 | 越高越好 |
| `top1_accuracy` | 分类探针在动作类别上的 top-1 准确率。 | 越高越好 |
| `macro_f1` | 分类探针的宏平均 F1。 | 越高越好 |
| `weighted_f1` | 分类探针按支持度加权的 F1。 | 越高越好 |
| `val_seen_mse` | 回归探针在 seen 验证集上的动作 MSE。 | 越低越好 |
| `val_unseen_mse` | 回归探针在 unseen 验证集上的动作 MSE。 | 越低越好 |

## 运行评测

目录 manifest 记录的 validation 命令：

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id larybench \
  --mode official-validation \
  --official-results-path <classification_summary.json_or_best_result.json> \
  --stage <classify_or_regress> \
  --output-dir <out> \
  --json
```

## 权重与环境变量

- `WORLDFOUNDRY_LARYBENCH_RESULTS_PATH`: 未显式传 `--official-results-path` 时，导入器默认从该路径读取官方结果导出文件。
- `DATA_DIR`: 本地官方数据集根目录。
- `LARY_METADATA_DIR`: 本地 benchmark 元数据根目录。
- `LARY_LA_DIR`: 存放已抽取 latent action 的目录。
- `MODEL_DIR`: 存放表征模型权重的本地根目录。

## 输出文件

运行会在 `--output-dir` 下写出：

- `scorecard.json`: WorldFoundry 统一 scorecard，记录上表中的指标值。
- `benchmark_contract.json`: 本次运行的 benchmark contract 记录（输入、模式、来源信息）。
- `raw_metric_table.jsonl`: 支撑 scorecard 的原始 metric 行。

Scorecard 主键：`extraction_coverage`（leaderboard key `extraction_coverage`），写入 `scorecard.json`。

## 边界与限制

- 完整 leaderboard 对齐需要完整官方分割、精确的表征模型权重、官方探针配置以及留存的运行产物。
- 只有当抽取设置（stride、mode、split）一致时，分类与回归得分才可跨模型比较。
- 大体量的分类视频、机器人图像对、轨迹与元数据通过 `DATA_DIR` 在包外就位。
