## About

**Publisher:** UCLA & Google Research

VideoPhy tests whether text-to-video models generate videos that follow real-world physical commonsense in material interactions (solid-solid, solid-fluid, fluid-fluid). Each prompt describes a physical interaction; generated videos are judged for Semantic Adherence (does the video match the prompt) and Physical Commonsense (does the motion obey physics), combined into a Joint Score. The official judge is VideoCon-Physics, a fine-tuned video-language model released by the authors.

WorldFoundry bundles the official prompt list and hosts the runner with two paths: normalizing caller-provided official result files, and executing the in-tree VideoCon-Physics AutoEvaluator judge via `--run-official`.

Official references:

- Paper: [arxiv.org/abs/2406.03520](https://arxiv.org/abs/2406.03520)
- Project page: [videophy.github.io](https://videophy.github.io/)
- Official repository: [Hritikbansal/videophy](https://github.com/Hritikbansal/videophy)

## Evaluation protocol

`official-validation` normalizes an official result export. `--run-official` drives the VideoCon-Physics judge over candidate videos: key flags include `--videocon-checkpoint` (judge weights), `--num-frames`, `--batch-size`, and the binarization thresholds `--sa-threshold` / `--pc-threshold` used to convert judge probabilities into per-video adherence decisions before aggregation.

Primary metric: `videophy_average`.

| Metric | Meaning | Direction |
| --- | --- | --- |
| `semantic_adherence` | Semantic Adherence normalized benchmark score. | Higher is better |
| `physical_commonsense` | Physical Commonsense normalized benchmark score. | Higher is better |
| `joint_score` | Joint Score normalized benchmark score. | Higher is better |
| `videophy_average` | VideoPhy Average normalized benchmark score. | Higher is better |

## Data and artifact layout

In-tree paths:

```text
worldfoundry/data/benchmarks/tasks/external/videophy.yaml

```

```text
worldfoundry/data/benchmarks/assets/videophy/prompts.json    # official prompt list
${WORLDFOUNDRY_GENERATED_ARTIFACT_DIR}/                      # candidate videos named per prompt id
```

The VideoCon-Physics judge checkpoint is caller-supplied (`--videocon-checkpoint`); it is not vendored in tree.

## Run the benchmark

Catalog-recorded validation command:

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id videophy \
  --mode official-validation \
  --official-results-path <official_results.json> \
  --generated-artifact-dir <generated_videos> \
  --output-dir <out> \
  --json
```

Execute the in-tree VideoCon-Physics judge over candidate videos:

```bash
${WORLDFOUNDRY_UNIFIED_PYTHON} \
  worldfoundry/evaluation/tasks/execution/runners/videophy/run_videophy_official_runner.py \
  --run-official \
  --generated-artifact-dir "${WORLDFOUNDRY_GENERATED_ARTIFACT_DIR}" \
  --videocon-checkpoint /path/to/videocon_physics \
  --output-dir tmp/videophy/official \
  --json
```

## Checkpoints and environment variables

- `WORLDFOUNDRY_VIDEOPHY_ROOT`: Optional override pointing at a local benchmark runtime/repository root.
- `WORLDFOUNDRY_VIDEOPHY_JUDGE_BACKEND`: Selects the judge backend for --run-official.
- `WORLDFOUNDRY_VIDEOPHY_RESULTS_PATH`: Default path the importer reads official result exports from when `--official-results-path` is not passed.
- `WORLDFOUNDRY_GENERATED_ARTIFACT_DIR`: Directory containing the candidate generated artifacts to score or import against.

## Outputs

The run writes into `--output-dir`:

- `scorecard.json`: WorldFoundry scorecard with the metric values recorded above.
- `benchmark_contract.json`: Benchmark contract record for the run (inputs, mode, provenance).
- `raw_metric_table.jsonl`: Metric rows backing the scorecard.

Scorecard primary key: `videophy_average` (leaderboard key `videophy_average`), stored in `scorecard.json`.

## Limitations

- The full official runtime remains upstream; the in-tree contract fixture records input/output shape only.
- Leaderboard parity requires the official VideoCon-Physics checkpoint, the full official prompt suite, and normalized upstream result files.
- Local judge runs over partial prompt sets are development signals, not official VideoPhy numbers.
