## About

**Publisher:** UC Berkeley (RAIL Lab)

BridgeData V2 is UC Berkeley RAIL's large-scale real-robot manipulation dataset — 60k+ trajectories on a low-cost WidowX arm across 24 environments — designed for training and evaluating broadly generalizing robot policies with language- and goal-image conditioning. Evaluation reports task success over scripted real-robot or offline protocols.

WorldFoundry integrates BridgeData V2 as an official-results runner: policy evaluation exports (task/goal success, action accuracy, rollout success) are normalized into the unified scorecard; dataset materialization and policy rollouts stay upstream.

Official references:

- Paper: [arxiv.org/abs/2308.12952](https://arxiv.org/abs/2308.12952)
- Project page: [rail-berkeley.github.io/bridgedata](https://rail-berkeley.github.io/bridgedata/)
- Official repository: [rail-berkeley/bridge_data_v2](https://github.com/rail-berkeley/bridge_data_v2)
- License: `mit`

## Evaluation protocol

WorldFoundry integrates this benchmark through the unified result-import path: `worldfoundry-eval zoo benchmark-run --mode official-validation` normalizes a caller-provided official result export (JSON/CSV rollout summaries) into the WorldFoundry scorecard without executing the simulator. Simulator execution, policy loading, and rollout collection remain explicit upstream steps performed with the official tooling.

Primary metric: `success_rate`.

| Metric | Meaning | Direction |
| --- | --- | --- |
| `success_rate` | Primary episode success rate over evaluated rollouts. | Higher is better |
| `task_success` | Per-task success aggregate. | Higher is better |
| `goal_success` | Goal-image-conditioned task success. | Higher is better |
| `action_accuracy` | Offline action-prediction accuracy against reference actions. | Higher is better |
| `rollout_success` | Success rate over executed policy rollouts. | Higher is better |

The dataset is staged under `${WORLDFOUNDRY_DATA_DIR}/datasets/bridgedata-v2`; the official download is HTTP/project-page based rather than a single Hugging Face table.

## Run the benchmark

Catalog-recorded validation command:

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id bridgedata-v2 \
  --mode official-validation \
  --official-results-path <official_results.json> \
  --output-dir <out> \
  --json
```

## Checkpoints and environment variables

- `WORLDFOUNDRY_BRIDGEDATA_V2_RESULTS_PATH`: Default path the importer reads official result exports from when `--official-results-path` is not passed.

## Outputs

The run writes into `--output-dir`:

- `scorecard.json`: WorldFoundry scorecard with the metric values recorded above.
- `raw_results.jsonl`: Normalized rows parsed from the official result export.

Scorecard primary key: `success_rate` (leaderboard key `success_rate`), stored in `scorecard.json`.

## Limitations

- Dataset materialization, eval-split definition, and policy-result import validation are prerequisites for integrated status.
- WorldFoundry does not run real-robot or simulated rollouts for BridgeData V2; action normalization and task-goal mapping follow the upstream protocol.
- Imported scorecards are integration evidence, not leaderboard submissions.
