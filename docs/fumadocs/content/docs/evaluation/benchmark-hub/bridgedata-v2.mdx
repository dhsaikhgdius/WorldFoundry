## About

BridgeData V2 is a large, diverse dataset of real-robot manipulation demonstrations (60k+ trajectories on a WidowX 250 arm across many scenes and skills) used to train and evaluate generalizable, open-vocabulary robot policies. Evaluation is conducted by rolling out policies on tasks drawn from the dataset distribution and reporting success rates; unlike simulator benchmarks, official evaluation involves real-robot or offline protocols defined by the authors.

WorldFoundry integrates BridgeData V2 as an official result normalizer only: caller-provided evaluation result files are converted into WorldFoundry scorecards. There is no in-tree simulator adapter (the simulator registry explicitly keeps BridgeData V2 normalizer-only), and no rollout execution is performed in this tree.

Official references:

- Paper: [arXiv:2308.12952](https://arxiv.org/abs/2308.12952)
- Project page: [rail-berkeley.github.io/bridgedata](https://rail-berkeley.github.io/bridgedata/)

- Result normalizer: `worldfoundry.evaluation.tasks.embodied.normalizer` (track `vla`)
- No simulator adapter and no closed-loop eval config exist for this benchmark id.

## Evaluation protocol and data layout

The catalog declares the dataset root as `${WORLDFOUNDRY_DATA_DIR}/datasets/bridgedata-v2` with split `eval`. Dataset materialization, eval-split definition, action normalization, and task-goal mapping are caller responsibilities (catalog `requires`).

For result import, the embodied normalizer accepts JSON, JSONL, CSV, TSV, and `result.txt`-style logs. Rows are matched on numeric fields such as `success`, `success_rate`, `task_success`, `goal_success`, `action_accuracy`, and `rollout_success`; booleans and percent strings are coerced to unit-interval floats.

## Metrics

Primary metric (scorecard key): `success_rate`.

| Metric | Meaning |
| --- | --- |
| `success_rate` | Share of evaluation rollouts completed successfully; primary leaderboard value. |
| `task_success` | Per-task success aggregated across rollouts. |
| `goal_success` | Goal-conditioned success where the protocol distinguishes goals from tasks. |
| `action_accuracy` | Agreement of predicted actions with reference actions in offline protocols. |
| `rollout_success` | Per-rollout binary success, when reported separately. |

Success metrics are normalized via the shared registry (`percent_or_fraction_to_unit`). No video-generation metrics apply.

## Preparation and environment

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_BRIDGEDATA_V2_RESULTS_PATH=/path/to/bridgedata_v2_results.json
```

The runtime profile configures only the generic Python environment (`needs_new_env: false`); it does not download the dataset or stage any robot runtime.

Verify runtime wiring:

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile bridgedata-v2 \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/bridgedata-v2.yaml \
  --output-dir tmp/worldfoundry_preflight/bridgedata-v2 \
  --json
```

## Import official results (official-validation)

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id bridgedata-v2 \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_BRIDGEDATA_V2_RESULTS_PATH}" \
  --output-dir tmp/bridgedata-v2/official-validation \
  --json
```

This routes through the embodied `vla`-track normalizer in-process. There is no in-tree `official-run` rollout path for BridgeData V2 — evaluations must be produced with the upstream tooling or real-robot setup and then imported.

## Outputs

- `scorecard.json`: WorldFoundry scorecard; leaderboard block keyed by `success_rate`.
- `raw_results.jsonl`: extracted raw result rows.
- `evaluation/summary.json`: aggregated per-metric statistics.
- `evaluation/per_sample_metrics.jsonl`: normalized per-rollout rows.

## What this page does not claim

- Catalog status is `normalizer_only` with `leaderboard_valid: false` and `official_benchmark_verified: false`. Imported numbers are normalized copies of caller-provided results, not officially reproduced leaderboard values.
- The BridgeData V2 dataset is not bundled; dataset materialization, split definition, and policy-result import validation remain open (catalog blocker).
- No robot or simulator execution happens in this tree; nothing on this page implies local rollout capability.
