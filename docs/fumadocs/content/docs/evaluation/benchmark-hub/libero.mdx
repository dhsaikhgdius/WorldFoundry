## About

LIBERO (LIfelong learning BEnchmark on RObot manipulation) evaluates knowledge transfer in lifelong/multitask robot learning. It defines 130 language-conditioned manipulation tasks organized into suites that isolate different transfer axes: LIBERO-Spatial (spatial relations), LIBERO-Object (object types), LIBERO-Goal (task goals), and LIBERO-100 (split as LIBERO-10 and LIBERO-90 for long-horizon and pretraining mixtures). Policies are scored by rollout success in a robosuite/MuJoCo simulator.

WorldFoundry integrates LIBERO with an in-tree closed-loop simulator adapter at `worldfoundry/evaluation/tasks/embodied/simulators/libero/` (suite aliases `libero-spatial`, `libero-object`, `libero-goal`, `libero-10`, `libero-90`) plus an official result normalizer for caller-provided rollout dumps. The catalog verification status is `normalizer_only`: result import is verified, while full leaderboard parity still requires a recorded LIBERO/OpenVLA parity run with simulator assets.

## In-tree integration

- Catalog: `worldfoundry/data/benchmarks/catalog/embodied/libero.yaml`
- Task manifest: `worldfoundry/data/benchmarks/tasks/external/libero.yaml`
- Runtime profile: `worldfoundry/data/benchmarks/runtime_profiles/official/libero.yaml`
- Simulator adapter: `worldfoundry/evaluation/tasks/embodied/simulators/libero/`
- Closed-loop eval configs: `worldfoundry/data/benchmarks/eval_configs/embodied/libero/{spatial,object,goal,10,90,all}.yaml`
- Result normalizer: `worldfoundry.evaluation.tasks.embodied.normalizer` (track `vla`)

## Evaluation protocol and result layout

For result import, the embodied normalizer accepts JSON, JSONL, CSV, TSV, and `result.txt`-style logs. Rows are matched on numeric fields such as `success`, `success_rate`, `task_success`, `episode_success`, and `action_accuracy`; booleans and percent strings are coerced to unit-interval floats, and episode identity is read from `sample_id`/`episode_id`/`task_id`/`task`/`id`/`name`.

The bundled `spatial.yaml` eval config runs suite `libero_spatial` with seed 7, 10 simulator warm-up steps, 50 episodes per task over up to 10 tasks, against an external policy server at `ws://localhost:8000`. The other suite configs follow the same shape with their respective suites.

## Metrics

Primary metric (scorecard key): `success_rate`.

| Metric | Meaning |
| --- | --- |
| `success_rate` | Share of rollouts completed successfully; primary leaderboard value. |
| `task_success` | Per-task success aggregated across episodes. |
| `episode_success` | Per-episode binary success. |
| `action_accuracy` | Agreement of predicted actions with reference actions where reported. |

Success metrics are normalized via the shared registry (`percent_or_fraction_to_unit`). No video-generation metrics apply.

## Preparation and environment

```bash
cd /path/to/WorldFoundry
export WORLDFOUNDRY_LIBERO_ROOT=/path/to/LIBERO            # official checkout, cached at cache/vla_va_wam/repos/Lifelong-Robot-Learning--LIBERO
export WORLDFOUNDRY_LIBERO_RESULTS_PATH=/path/to/libero_results.json
```

Closed-loop rollouts require the LIBERO package (importable in the unified env per the runtime profile), the LIBERO dataset root or a LeRobot conversion, and a suite-specific policy checkpoint served over WebSocket.

Verify runtime wiring without launching the simulator:

```bash
python -m worldfoundry.evaluation.tasks.execution.orchestration.runtime_preflight \
  --profile libero \
  --manifest worldfoundry/data/benchmarks/runtime_profiles/official/libero.yaml \
  --output-dir tmp/worldfoundry_preflight/libero \
  --json
```

## Import official results (official-validation)

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id libero \
  --mode official-validation \
  --official-results-path "${WORLDFOUNDRY_LIBERO_RESULTS_PATH}" \
  --output-dir tmp/libero/official-validation \
  --json
```

This routes through the embodied `vla`-track normalizer in-process; no simulator code is executed.

## Closed-loop rollouts (native simulator)

With LIBERO installed and a policy server running:

```bash
worldfoundry-eval embodied run \
  --config worldfoundry/data/benchmarks/eval_configs/embodied/libero/spatial.yaml \
  --output-dir tmp/libero/embodied-run \
  --json
```

Swap the config for `object.yaml`, `goal.yaml`, `10.yaml`, `90.yaml`, or `all.yaml` to run the other suites. `--server-url`, `--shard-id`/`--num-shards`, and `--no-docker` are supported.

## Outputs

- `scorecard.json`: WorldFoundry scorecard; leaderboard block keyed by `success_rate`.
- `raw_results.jsonl`: extracted raw result rows.
- `evaluation/summary.json`: aggregated per-metric statistics.
- `evaluation/per_sample_metrics.jsonl`: normalized per-episode rows.

## What this page does not claim

- Catalog status is `normalizer_only` with `leaderboard_valid: false` and `official_benchmark_verified: false`. Imported numbers are normalized copies of caller-provided results, not officially reproduced leaderboard values.
- LIBERO simulator assets, datasets, and policy checkpoints are not bundled; closed-loop rollouts require an external LIBERO installation and a policy server. No local GPU rollout evidence is claimed.
- Full leaderboard parity still requires an official LIBERO rollout execution with simulator assets, policy checkpoints, and upstream evidence (catalog blocker).
