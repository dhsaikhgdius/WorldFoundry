## 简介

**发表机构：** Peking University（北京大学 DAGroup）与 ByteDance Seed

RBench（出自 ReVidgen 项目，ICML 2026）评测面向机器人的图生视频。650 个图文样例分为任务导向集（250 例，覆盖常规操作、长时程规划、多主体协作、空间关系与视觉推理）与形态导向集（400 例，覆盖双臂、人形、单臂与四足机器人）。视频由 VLM judge（GPT 或 Qwen3-VL）按物理合理性、任务遵循与稳定性打分，另有来自 GroundingDINO/SAM2/CoTracker/Q-Align 栈的算子指标（运动平滑度与幅度）；benchmark 与人工评估的 Spearman 相关系数达 0.96。配套的 RoVid-X 数据集提供 400 万条带标注机器人片段用于训练。

WorldFoundry 仓内 scorer 从逐视频输出复现官方 `eval/4_embodiments` 与 `eval/5_tasks` 聚合——包括选项到分数映射、min-max 归一化、PAS 与一致性罚分，以及丢弃无可测运动幅度视频的幅度过滤器。

官方参考：

- Paper: [arxiv.org/abs/2601.15282](https://arxiv.org/abs/2601.15282)
- 官方仓库: [DAGroup-PKU/ReVidgen](https://github.com/DAGroup-PKU/ReVidgen)

## 评测协议

把 `--official-results-path` 指向 RBench results 根目录（或单个赛道/模型目录）；结果树含多个生成模型时用 `--result-model-id` 选定；GPT 与 Qwen judge 输出并存时用 `--vlm-backend` 指定——两者绝不混入同一次聚合。`--track` 限定单一赛道；`--generated-artifact-dir` 提供覆盖率报告。

主指标是 `rbench_overall`。

| Metric | 含义 | 方向 |
| --- | --- | --- |
| `rbench_overall` | WorldFoundry 对两条官方赛道得分的合成均值；不是已发表的 RBench 数字。 | 越高越好 |
| `embodiment_overall` | 四种机器人本体上任务完成与视觉质量的汇总。 | 越高越好 |
| `task_completion` | 归一化物理合理性与任务遵循一致性的均值。 | 越高越好 |
| `visual_quality` | 扣除幅度与一致性罚分后的加权稳定性与平滑度得分。 | 越高越好 |
| `visual_quality_base` | 0.8 × 机器人主体稳定性 + 0.2 × 运动平滑度（未扣分前）。 | 越高越好 |
| `physical_plausibility` | 由 1-5 分制归一化的 VLM 物理合理性得分。 | 越高越好 |
| `task_adherence_consistency` | 由 1-5 分制归一化的 VLM 任务遵循得分。 | 越高越好 |
| `robot_subject_stability` | 由 1-15 选项映射分制归一化的 VLM 机器人与物体稳定性得分。 | 越高越好 |
| `motion_smoothness` | 运动平滑度算子得分。 | 越高越好 |
| `motion_amplitude` | 驱动 PAS 扣分的机械臂可感知幅度算子得分。 | 越高越好 |
| `task_track_overall` | 五个任务分组内所有已评分视频的 ALL_TASKS_MEAN 汇总。 | 越高越好 |
| `common_manipulation` | common manipulation（常规操作）分组的归一化 rubric 得分。 | 越高越好 |
| `long_horizon_planning` | long-horizon planning（长时程规划）分组的归一化 rubric 得分。 | 越高越好 |
| `multi_entity_collaboration` | multi-entity collaboration（多实体协作）分组的归一化 rubric 得分。 | 越高越好 |
| `spatial_relationship` | spatial relationship（空间关系）分组的归一化 rubric 得分。 | 越高越好 |
| `visual_reasoning` | visual reasoning（视觉推理）分组的归一化 rubric 得分。 | 越高越好 |

## 运行评测

目录 manifest 记录的 validation 命令：

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id rbench \
  --mode official-validation \
  --official-results-path <rbench_results_root> \
  --result-model-id <model_id> \
  --output-dir <out> \
  --json
```

## 权重与环境变量

- `WORLDFOUNDRY_RBENCH_RESULTS_PATH`: 未显式传 `--official-results-path` 时，导入器默认从该路径读取官方结果导出文件。
- `WORLDFOUNDRY_RBENCH_DATA_ROOT`: DAGroup-PKU/RBench prompt 与图像套件的本地根目录。
- `WORLDFOUNDRY_RBENCH_VLM_BACKEND`: 默认聚合哪个 VLM judge 的输出。
- `WORLDFOUNDRY_GENERATED_ARTIFACT_DIR`: 存放待评测生成产物（候选视频/rollout）的目录。

## 输出文件

运行会在 `--output-dir` 下写出：

- `scorecard.json`: WorldFoundry 统一 scorecard，记录上表中的指标值。
- `benchmark_contract.json`: 本次运行的 benchmark contract 记录（输入、模式、来源信息）。
- `raw_metric_table.jsonl`: 支撑 scorecard 的原始 metric 行。
- `track_breakdown.json`

Scorecard 主键：`rbench_overall`（leaderboard key `rbench_overall`），写入 `scorecard.json`。

## 边界与限制

- WorldFoundry 只聚合所提供的 judge 与算子输出；不在仓内运行 VLM judge 或 GroundingDINO/SAM2/CoTracker/Q-Align 栈。
- `rbench_overall` 是 WorldFoundry 对两条赛道得分的合成值，不是 RBench 官方发布数字。
- GPT 与 Qwen judge 输出绝不混合；每次聚合只用一个后端。
