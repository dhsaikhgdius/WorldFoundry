## About

**Publisher:** The University of Hong Kong & Shanghai AI Laboratory (with AgileX Robotics)

RoboTwin 2.0 is a scalable simulation benchmark for bimanual robotic manipulation: 50 dual-arm tasks over 731 objects across five embodiments, with an automated expert-data generator and systematic domain randomization (clutter, lighting, backgrounds, tabletop heights, language instructions) designed to measure robustness — clean vs. randomized success are tracked separately. The companion pre-collected dataset exceeds 100k trajectories.

WorldFoundry imports official `eval_result/_result.txt` and structured JSON/CSV exports into scorecard artifacts, including a task manifest, official command manifest, and simulator-validation record. Offline normalization needs no simulator; real parity requires the upstream SAPIEN/Curobo stack.

Official references:

- Paper: [arxiv.org/abs/2506.18088](https://arxiv.org/abs/2506.18088)
- Project page: [robotwin-platform.github.io](https://robotwin-platform.github.io/)
- Official repository: [RoboTwin-Platform/RoboTwin](https://github.com/RoboTwin-Platform/RoboTwin)

## Evaluation protocol

Offline normalization accepts explicit official `eval_result/_result.txt` or structured exports via `--official-results-path` / `WORLDFOUNDRY_ROBOTWIN_RESULTS_PATH`. Real simulator/policy parity requires upstream SAPIEN/Curobo assets and policy checkpoints executed with the official scripts.

Primary metric: `success_rate`.

| Metric | Meaning | Direction |
| --- | --- | --- |
| `success_rate` | Primary episode success rate over evaluated rollouts. | Higher is better |
| `task_success` | Per-task success aggregate. | Higher is better |
| `episode_success` | Per-episode success indicator aggregate. | Higher is better |
| `bimanual_task_success` | Success aggregate over dual-arm coordination tasks. | Higher is better |
| `domain_randomization_success` | Success under the official domain-randomized condition. | Higher is better |
| `clean_success` | Success under the clean (non-randomized) condition. | Higher is better |
| `randomized_success` | Success under randomized clutter/lighting/background conditions. | Higher is better |
| `reward` | Mean episode reward / return. | Higher is better |

## Run the benchmark

Catalog-recorded validation command:

```bash
worldfoundry-eval zoo benchmark-run \
  --benchmark-id robotwin \
  --mode official-validation \
  --official-results-path <official_results.json> \
  --output-dir <out> \
  --json
```

## Checkpoints and environment variables

- `WORLDFOUNDRY_ROBOTWIN_ROOT`: Optional override pointing at a local benchmark runtime/repository root.
- `WORLDFOUNDRY_ROBOTWIN_RESULTS_PATH`: Default path the importer reads official result exports from when `--official-results-path` is not passed.

This benchmark reuses the shared base-model dependency stack: `robotwin_dataset_assets`.

## Outputs

The run writes into `--output-dir`:

- `scorecard.json`: WorldFoundry scorecard with the metric values recorded above.
- `benchmark_contract.json`: Benchmark contract record for the run (inputs, mode, provenance).
- `task_manifest.json`
- `official_command_manifest.json`
- `simulator_validation.json`
- `raw_metric_table.jsonl`: Metric rows backing the scorecard.
- `evaluation/per_sample_metrics.jsonl`

Scorecard primary key: `success_rate` (leaderboard key `success_rate`), stored in `scorecard.json`.

## Limitations

- Result import is normalizer-only; full leaderboard parity requires executing the upstream SAPIEN/Curobo simulator and policy scripts with staged assets and checkpoints.
- A 2026-05-25 bounded simulator validation reached CUDA driver allocation locally, but upstream `script/test_render.py` exceeded the hard timeout; SAPIEN/Vulkan rendering remains blocked in this environment.
- RoboTwin 2.0 is an embodied bimanual-manipulation benchmark, not a video-generation benchmark.
