## 如何读懂状态列

每个模型都有一个就绪度徽章。徽章由相互独立的 manifest 记录计算得出，缺失的证据永远不会被四舍五入成更强的声明。

| 状态 | 含义 | 你可以做什么 |
| --- | --- | --- |
| **Runner verified** | 至少一条路径已记录 WorldFoundry runner parity 产物。 | 复制运行命令，可以预期得到已记录的 artifact。 |
| **Integrated** | 已绑定可运行 Pipeline，但端到端 GPU parity 仍在验证。 | 可以运行；在 parity 记录之前，输出应视为未验证。 |
| **Runtime ported** | 运行时代码已在仓库中，路径还在接线。 | 检查 manifest；运行可能需要手动步骤。 |
| **Profile only** | 只记录了 runtime profile，没有绑定 Pipeline。 | 页面可用于溯源与规划；不会显示运行命令。 |
| **Planned** | 条目只记录了意向与上游来源。 | 可以跟踪；目前没有可运行内容。 |
| **Blocked** | 已记录的 blocker（许可、权重、上游）阻止了集成。 | 阅读 manifest 备注了解具体 blocker。 |

## 如何选择模型

1. **按家族和任务过滤。** 使用分类标签（视频、世界模型、3D 与 4D、具身智能、托管 API）和搜索框——搜索会匹配模型名、别名、提供方和任务 id。
2. **优先选择 verified 或 integrated 条目。** 这些条目已绑定 Pipeline；其余条目只是参考资料。
3. **检查运行时列。** 独立环境需要单独安装；统一环境的模型共享一个 conda 环境。Python/CUDA 列可以在安装前告诉你驱动栈是否匹配。
4. **打开模型页面。** 每个页面都会解释模型是什么、来自哪里、输入/输出契约、精确的环境、带固定 revision 的权重仓库，以及为所选 variant 生成可复制运行命令的命令构建器。

## 每个模型页面包含什么

模型页面由 `docs/fumadocs/scripts/generate-model-recipes.py` 从仓库 manifest 生成，而不是人工维护的宣传页。每个页面会把下面几类声明分开呈现：

| 记录 | 可以确认什么 |
| --- | --- |
| Catalog | 稳定 model ID、任务、官方来源（论文、项目、代码、权重）、别名和集成状态。 |
| Runtime profile | 输入契约、artifact 契约、backend stage 和运行时就绪状态。 |
| Environment | Python、CUDA tier、固定依赖、验证 import，以及独立/统一环境路由。 |
| Pipeline binding | WorldFoundry 使用的 runner 与每个 variant 的具体 pipeline target。 |
| Benchmarks | Manifest 推荐或其证据记录中提到的评测，链接到 Benchmark Hub。 |
| Evidence | 原生 demo 与 WorldFoundry runner 的 parity；只有 catalog 记录并不代表 GPU 已验证。 |

缺失值会明确显示为**未记录**。Catalog manifest 还可以携带人工撰写的 `docs:` 块（概述、亮点、用途、硬件建议、推荐评测、限制，全部双语）；当该块缺失时，生成器会从已记录字段合成等效的叙述，因此每个页面无论如何都保持详细。

## 常用命令

```bash
# 检查完整 catalog manifest。
worldfoundry-eval zoo model-show \
  --model-id <model-id> \
  --include-manifest \
  --json

# 不下载，只解析 checkpoint、凭据与本地资产 blocker。
worldfoundry-eval zoo model-download \
  --model-id <model-id> \
  --check-local \
  --json

# 为一个 runtime profile 解析并安装环境 manifest。
bash scripts/setup/model_env_install.sh --model <model-id>

# 为一个 runtime profile 下载 checkpoint 与源码资产。
bash scripts/inference/prepare_model_infer.sh <model-id>

# 运行一个已记录的 task profile（每个模型页面会生成精确的参数）。
worldfoundry-eval run <model-id> --pipeline.task-profile <task> --json
```
